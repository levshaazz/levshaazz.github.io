# Topic 04: byte-level explanation and actual local API smoke

`fixture.json` is a deterministic **illustration** generated by
`teaching/topic04_sse.py`. The literal request is “Say café ☕ briefly.” Its response,
usage counts and arrival clocks are invented, not tokenizer or GPU measurements.
The 16 byte chunks intentionally split UTF-8 characters and CRLF delimiters.
Seven wire records include one heartbeat comment and six data events: role,
two content events, finish, usage, and `[DONE]`. Five events contain JSON.

`capture.json` is a different, real local API recording. Its raw probe says
“Say hello briefly.” The nonstream/SDK prompt asks for a short sentence explaining
an API server. The exact locally rendered chat, token IDs and pieces are retained;
the returned prompt-token count is checked against local tokenization. Equal
counts alone do not prove byte-for-byte server template identity.

The real raw transcript preserves client-received byte chunks and their arrival
times, decoded SSE events, terminal status, content and usage. Its bytes replay
without a model, network request or GPU. A byte chunk, an SSE event, a content
delta and a generated token are different units; never substitute their counts.

## Explicit scope

- One local pinned 0.5B vLLM service, loopback only, context 2048, at most four
  sequences and a 45% memory target. This is an API smoke, not concurrent capacity.
- Nonstream, SDK stream and raw HTTP/SSE are separate requests. No automatic
  request retry. First API call may include lazy runtime initialization.
- Stream timing is client-observed wall time. First event, first nonempty content,
  finish and terminal `[DONE]` are different boundaries, not GPU kernel timings.
- The raw client uses WHATWG UTF-8/SSE framing but a deliberately narrower
  **text-only, single-choice** chat profile. It rejects unsupported nontext deltas,
  invalid UTF-8/JSON, malformed lifecycle, nonmonotonic clocks and bounded overflow.
  A partial response is not successful completion.
- Synthetic cancellation exercises client classification only. Actual engine
  cancellation, KV reclamation, proxies, concurrent load and billing were not tested.
- Wrong served name and bounded over-context request must return real 4xx status.
  A timeout, disconnected server or unexpected success is not a passing negative test.
- Teardown owns only the server process group created by the helper. It does not
  kill arbitrary GPU processes; external SIGTERM unwinds the cleanup path.

The source commit, source/capture SHA-256 hashes, verified memory envelope and run
duration are in `provenance.json`. The private `server.local.log` is not published.
No credentials, private judge inputs, student data or production SLOs are included.

Framing source: [WHATWG event streams](https://html.spec.whatwg.org/multipage/server-sent-events.html).

## Recorded execution and one bounded correction

The first attempt on source `7c23155` stopped **before launching the server**:
the cached Transformers 5.17 tokenizer returned a `BatchEncoding`, while the
initial recorder expected a plain ID list. Its failed private provenance is kept.
The correction normalizes the two supported return forms, accepts only one
sequence and rejects malformed or multiple batches. CPU fixtures and an actual
offline tokenizer check passed before a new clean checkpoint was created.

The successful capture used source `d925e2b792ac2f395c4b963c2bb51c477db8c983`,
completed in 30.811 s, startup 24.456 s. It ran offline under an effective 24 GiB
RAM/no-swap scope, 900 s external timeout and 45 s kill grace. After owned-group
teardown and process exit, GPU use was 0 MiB with no compute process. A runtime
shutdown warning reported one semaphore for Python's resource tracker to clean;
it did not leave the owned process group or a GPU compute process running.

The main request used 41 input + 29 completion IDs. The raw probe used 33 + 10,
returned `Hello! How can I assist you today?`, and produced 13 data events in 13
observed byte reads (2718 bytes). Equality of those two counts in **this** recording
is coincidental, not a framing guarantee. The synthetic fixture deliberately
breaks that equality. Wrong model returned 404; the 2329-input-ID probe returned
400. No concurrency, server-side cancellation or judge reference was run.
