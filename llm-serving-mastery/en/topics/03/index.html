Use the lab ZIP to obtain the matching runner and real-layer data; upload both into Colab before running. Slides, Book and lab remain in revision until teaching review and a learner pilot.

Learning outcomes

  1. Derive scales and implement row-local grouped quantization; measure output error and metadata costs; explain AWQ scaling and GPTQ compensation.
  2. Run the pinned FP16/NF4 comparison, changing only fixed output length from 24 to 96; preserve raw timings and natural ticket answers.
  3. Make a bounded keep/reject/inconclusive decision with one prediction checked against evidence (supported, revised or unresolved) and a discriminating next experiment.

Acceptance checklist

  • Implement derive_scale and quantize_groups; compare None/4/2/1, measure weight and output MSE on base and held-out inputs. Timing statistics are provided.
  • On the real Qwen slice, compare tensor/row/128/64/32 groups; plot matched distributions, minimize calibration user-only output error under 4.30 ideal bits/weight, freeze the choice, then evaluate held-out without reselection.
  • Explain equivalent AWQ scaling and GPTQ compensation with the worked numbers before GPU execution; full method implementations are optional.
  • Change only 24 → 96 fixed output IDs, paired across FP16 and NF4.
  • Hold model/tokenizer revision, input IDs, device, stack, batch and sampling fixed; representation and execution path change together.
  • Twenty timed trials are separate from twelve natural ticket outputs per format.
  • Distinguish payload, allocated, reserved and device-wide memory; allocator pools persist across lengths.
  • The tiny synthetic ticket set and five trials establish neither representative quality nor robust p95.
  • Preserve raw evidence, failures and cleanup; consistency validation does not prove authenticity.
  • Check one prediction against evidence (supported, revised or unresolved); name a limitation and a discriminating next test.

Reading route

  • Required: Book 03 sections 1–9, including AWQ/GPTQ numerical mechanisms; complete CPU work before the GPU A/B.
  • Optional: full AWQ/GPTQ implementations and derivations, FP8/NVFP4, alternate kernels and capacity experiments.

Open the primary sources

  • MIT EfficientML 2024 · teaching design — Adapted controlled changes and numerical simulation versus real storage; not the graduate workload or measured results.
  • CMU Deep Learning Systems · teaching design — Adapted progressive student implementation with executable tests, not solutions.
  • GPU Puzzles · teaching design — Adapted small executable exercises and transfer checks; no CUDA implementation required in this core.
  • bitsandbytes 0.50.2 · NF4 codebook and quantization functions — The actual nonuniform lookup values in the pinned lab runtime. The course signed-INT4 packing example is a separate invented format, not an implementation of these CUDA kernels.
  • Pinned Qwen2.5-0.5B-Instruct configuration — Pinned model dimensions for the teaching notebooks; use the recorded runtime and actual selected attention path.
  • GPTQ — Second-order post-training weight quantization; distinct from the NF4 teaching lab.
  • AWQ — Activation-aware weight quantization; not a generic name for all four-bit paths.
  • vLLM quantization support — Version- and hardware-sensitive format support; verify the installed release.
  • PyTorch 2.14 · CUDA execution and memory — Asynchronous execution, synchronization and the caching allocator. Allocated, reserved and whole-device memory are different quantities.
