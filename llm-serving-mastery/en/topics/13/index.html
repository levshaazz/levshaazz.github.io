The Pass and the Check

LLMOps: observability, monitoring & cost control

Green dashboards lie: a burst second hides inside the mean. Build the honest stack on the layer-2 journal — SLI/SLO with named windows, burn-rate alerts that fire for the right reason, a cost ledger with named levers, and batch-invariant evaluation whose verdicts reproduce. The journal hash chain makes the ground truth provable: an edited history is a detected event.

Learning outcomes

  1. Declare SLI/SLO with named windows and percentiles; explain why the mean hides a burst second.
  2. Aggregate the layer-2 journal into metrics and verify the hash chain before trusting a dashboard.
  3. Design a burn-rate alert with fast and slow windows; predict its false positives on a frozen trace.
  4. Build a cost ledger from measured tok/s and named prices; choose a lever with a predicted effect.
  5. Run the batch-invariant evaluation protocol; explain why a non-reproducible verdict is weather, not a score.
  6. Fill the incident runbook skeleton: symptom, query, lever, rollback — each row rehearsed.

Acceptance checklist

  • SLO names percentile and window
  • dashboard numbers trace to journal entries; chain verification ok:true attached
  • alert rules give a predicted false positive on the frozen teaching trace
  • cost ledger labels measured vs declared arithmetic
  • invariant evaluation re-run reproduces the verdict; runbook rows rehearsed
