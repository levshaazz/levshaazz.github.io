The Fleet Dispatcher

Kubernetes for LLM serving: GPU Operator & Helm

You already run a fleet — compose engines with limits, a hash-chained journal, shard replicas. Kubernetes turns that by-hand loop into declared state: the pod inherits the ledger (16+4)/p + 1.5 GiB and the 165 s cold start, the startupProbe budgets the boot (5 × 40 = 200 s ≥ 165 s), a rolling update with maxUnavailable 0 holds the capacity floor, and a Helm release is append-only history where rollback creates a new revision. The GPU dictionary — Operator, time-slicing, MIG — is honest vocabulary; the lab is a declared teaching model of a cluster, not your cluster.

Learning outcomes

  1. Size an LLM pod from the course ledger and declare it Guaranteed: requests == limits, nvidia.com/gpu: p.
  2. Budget a startupProbe so the boot is covered with named headroom; explain why liveness must not kill a booting pod.
  3. Choose maxUnavailable/maxSurge so a rolling update never dips capacity; read the floor as replicas − maxUnavailable.
  4. Drive Helm releases: upgrade, history, rollback — and explain why rollback creates revision 4 instead of rewinding.
  5. Name the GPU sharing words (time-slicing, MIG, MPS) and their isolation trade-offs.
  6. Produce a rollback runbook: manifest numbers, probe budget, the command, and the revision you expect after it.

Required artifacts

  • pod-manifest.yaml (requests == limits from the ledger; nvidia.com/gpu: p)
  • probe-budget.md (period × threshold vs the 165 s cold start, headroom named)
  • rollout-plan.md (replicas, maxUnavailable/maxSurge, the floor)
  • release-history.txt (revisions 1→4 with the rollback record)
  • rollback-runbook.md (numbers, command, expected revision)

Acceptance checklist

  • pod memory equals (16+4)/p + 1.5 GiB with requests == limits
  • probe budget ≥ 165 s with named headroom over the median boot
  • rollout floor held: capacity never below replicas − maxUnavailable
  • rollback from history [1,2,3] yields revision 4 with revision 1 content
  • the runbook names the exact revision that exists after the rollback
