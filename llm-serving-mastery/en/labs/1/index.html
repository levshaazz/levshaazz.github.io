Baseline: from one request to the streaming timeline

The interactive replacement for the seminar notebook: predict first, then run the deterministic engine, then read what the client actually measured.

seeded sim · request → SSE timeline · ≈ 30 min

The contract before code

Everything below is a declared teaching simulation: the timing model is printed in full, the seed is fixed, and the same request always produces the same timeline. It is not an engine benchmark — the pinned measurements stay in the evidence runs. The lab habit comes from the course contract: predict from the model, then measure, then explain the difference.

The declared engine model

download12.0 sinit3.0 swarm-up1.0 s
prefill40 ms + 0.625 ms × tokensdecode step60 msjitter±10 % (seed 20261114)

Reference scenario: 96-token prompt, 64 output tokens, streaming on.

Cold vs warm: watch the lifecycle

Press cold, then warm. The cold path pays weights download, engine init and one warm-up forward before the first token; the warm path starts serving immediately.

Predict, then check

Use the declared model only — nominal numbers, no jitter. Write a number, press Check. Close counts as almost: the model must be able to say why.

Q1

Q2

Warm start: how many milliseconds until the first token (TTFT)?

ms

Prefill for 96 tokens costs 40 + 96 × 0.625 ms; one decode step follows. Answer with the nominal number from the model — a sandbox measurement differs by up to ±10% jitter on purpose.

Q3

Warm start: how many seconds until the last of the 64 tokens arrives?

s

The first token arrives at TTFT; the other 63 follow one step each.
