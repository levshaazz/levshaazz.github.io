One matrix: derive scales, compare groups and outputs, understand AWQ/GPTQ, then evaluate one real FP16/NF4 GPU path.

1. One matrix and an output to preserve

Start with a trained model, not an isolated rounding rule. Our investigation uses Qwen/Qwen2.5-0.5B-Instruct at revision 7ae557604adf67be50417f59c2c2f167def9a775. A token ID selects an embedding; 24 decoder blocks transform it; the final normalization and vocabulary projection produce logits. We intervene only in block 12, counting from zero. This is a local numerical experiment, not quantization of the whole model.

Inside each pre-norm block, attention adds its result to a residual stream, and an MLP adds another result. Inside the MLP, a gate projection followed by SiLU multiplies an independent up projection elementwise. The down projection then maps 4864 intermediate features back to the 896-feature residual stream. Those intermediate features depend on the prompt, earlier layers and the nonlinear gate. They are not token IDs or attention probabilities.

To learn the arithmetic before handling millions of values, we now switch to a fully visible invented matrix. We return to the real distribution after deriving the scale; the toy numbers must never be presented as measurements of Qwen.

A linear layer multiplies input features by learned weights and adds their contributions. It consumes actual reconstructed numbers, not a file size or an average weight error. Our complete invented example has two output features and four input features, no bias and no activation function. It is not a slice of a trained model.

W = [[ .49,  .40, .60,  7.00],
     [-.31, -.60, .92, -1.40]]   # [out=2, in=4]
X = [[1, 1, 0, 0],
     [0, 1, 0, 0]]             # [samples=2, in=4]
Y = [[ .89, -.91],
     [ .40, -.60]]             # [samples=2, out=2]
# Y = X @ W.T

For the first input, output 0 is .49 + .40 = .89; output 1 is −.31 − .60 = −.91. Zero input features suppress the last two columns, but their weights still influence a global quantization scale. This distinction will motivate inspecting typical inputs.

2. Derive a scale; observe the outlier

Four bits permit sixteen patterns. Our signed container has codes −8 through 7. For symmetric range fitting we use magnitudes up to 7, leaving −8 unused. This deliberate convention makes the fitted positive and negative ranges equal; it is neither the only INT4 convention nor NF4. Zero point is fixed at zero, so no separate offset is stored.

Why divide by 7? Seven steps must cover the largest magnitude at the positive endpoint. Now .49/1 rounds to 0, .40 rounds to 0, .60 rounds to 1, and 7 stays 7. The negative row becomes [0,−1,1,−1]. Signed error always means reconstructed minus original.

RowOriginal weightsCodes and reconstructed values, step 1
0[.49,.40,.60,7][0,0,1,7]
1[−.31,−.60,.92,−1.40][0,−1,1,−1]

The outlier sets everybody's grid even on inputs where its own contribution is zero. As a diagnostic counterfactual, replace 7 by .70: maximum magnitude becomes 1.40, scale becomes .20, and .49 reconstructs to .40 instead of zero. Changing that weight changes the model, so deleting the outlier is not our solution. It reveals the cost of sharing a scale.

Nearest-even sends exact halfway values to the even code: at step 1, .5 becomes 0 and 1.5 becomes 2. Binary division may move decimal halfway cases slightly; use tolerances. Clipping is separate: an undersized step .25 maps 7 to requested code 28, clips to 7 and restores 1.75. The half-step error bound applies without saturation, not after arbitrary clipping.

3. Groups, bytes and input-dependent error

Per-output-channel means one scale per row in our [out,in] convention. Row 0 keeps scale 1; row 1 gets 1.40/7 = .20. Group size 2 instead splits each row along input features into [.49,.40], [.60,7], [−.31,−.60], [.92,−1.40]. Groups never cross rows. Their scales are .07, 1, .60/7 and .20.

For the first pair, .49/.07 is approximately 7 and .40/.07 is approximately 5.714. Codes [7,6] reconstruct approximately [.49,.42]. The first weight is preserved; the second has error +.02. The next pair still shares the outlier: .60 reconstructs to 1. Smaller groups do not repair every value.

Weight MSE averages eight squared weight errors; output MSE averages four squared output errors (two samples × two outputs). These are different quantities and denominators. Group-1 errors are near zero up to floating-point roundoff, not evidence of lossless four-bit compression: the scales now carry almost all the information.

Eight four-bit codes use four ideal payload bytes. Each assumed FP16 scale adds two bytes: global/row/group-2/group-1 totals are 6/8/12/20 bytes, versus 16 for eight FP16 weights. Even groups of size ggg give approximately 4+16/g4+16/g4+16/g bits per weight. A short tail needs another scale. Headers, alignment and actual FP16 scale-rounding error are omitted; arithmetic above uses unrounded Python scales. Do not call it the measured error of a packed kernel.

Keep the quantized weights fixed and try [10,0,0,1]. Global errors become [−4.90,+3.50]; group-2 errors become approximately [0,−.328571]. The larger first input feature amplifies its column's residual. This is a transfer check, not a generalization certificate.

The central zoom retains the same bins and vertical scale for all three panels, and still divides each bin by the total number of weights. Its outside-window percentage discloses hidden tails. For global rounding, values within half the step of zero map to zero, apart from exact tie conventions. Read this together with the full-range histogram: changing the visible window does not change the data or prove output preservation.

For real group-64 quantization, each row is split into 76 contiguous input-feature groups. There are 896 × 76 = 68,096 scales. The restored matrix can have many more than sixteen distinct floating-point values because every group has a different scale; each individual code still occupies four ideal bits. 4. Calibration, AWQ and GPTQ mechanisms

Range fitting reads only weights, but our target is the layer response. Calibration collects representative inputs to choose quantization parameters or corrections. Output squared error is a natural local objective and needs no task labels. In a model, inputs here are layer activations produced by calibration texts, not raw token IDs. Keep separate evaluation inputs: fitting a small calibration set does not establish task quality on other prompts.

Which positions should count?

The original six-prompt visual fragment included a 24-position common prefix: 72 of 120 calibration positions, or 60%, came before the user content. That capture remains historical, not silently overwritten. Our new study fixes twelve longer prompts across arithmetic, code, JSON extraction, Russian explanations, support and summarization. Each split contains one prompt from every domain. For example, calibration arithmetic asks for change after buying four $3 notebooks with $20; held-out arithmetic asks for average speed over two travel segments.

AWQ: rescale important input channels before rounding

AWQ uses activation information to find important weight channels and search for channel rescaling. An equivalent transformation protects them without requiring those weights to remain FP16. We isolate this mechanism, not reproduce its full search or reported accuracy. See AWQ, section 3.2.

To expose activation salience, explicitly change the calibration inputs to [10,1,0,0] and [0,1,0,0]. Feature 0 has mean absolute magnitude 5; feature 1 has 1. Keep W unchanged and try multipliers 1/2/4/32 for feature 0. At multiplier 2, .49 becomes .98. The maximum remains 7 and step remains 1: .98 rounds to 1. Dividing the effective weight by 2 yields .50 rather than baseline 0. Its first-sample error contribution changes from −4.90 to +.10.

Inverse input scaling is essential: changing only weights changes the layer even before quantization. Rounding does not commute with rescaling; equivalent float parameterizations can give different quantized outputs.

GPTQ: compensate remaining weights after each rounding

GPTQ rounds sequentially and uses calibration-derived second-order information to adjust still-unquantized weights. Correlated features let one weight replace part of another's lost contribution. Its practical algorithm uses damping, Cholesky factorization and blocked updates. This two-coordinate example omits those optimizations. See GPTQ, sections 3–4.

Return to [1,1,0,0] and [0,1,0,0]. Take row 0's first weights [.49,.40]; other input features are zero. Keep the original global step 1 fixed; do not recompute it from the slice. Rounding .49 to 0 loses .49 times feature 0. Allow correction aaa in the second weight. Before rounding that weight, residuals are −.49+a-.49+a−.49+a and aaa.

The second weight changes .40 → .645 → rounded 1. Final codes are [0,1], not independent [0,0]. Targets on the two samples are [.89,.40]. Independent rounding gives errors [−.89,−.40], output SSE .9521; compensation gives [.11,.60], SSE .3721. Here SSE sums two samples and one output; divide by two for that subproblem's MSE.

Weight SSE meanwhile rises .4001 → .6001! A worse weight approximation better preserves the joint calibration response. The second sample nevertheless worsens: .60 absolute error instead of .40. An aggregate objective does not promise improvement on every input or an unseen distribution.

The Gram matrix of the two active features is [[1,1],[1,2]]. Its off-diagonal entry is an uncentered cross-product: it measures how the features act together in this reconstruction objective. It is not Pearson correlation. In this two-sample toy the second feature is constant, so its centered Pearson correlation is undefined; it can still compensate part of the first feature's lost output. A zero cross-product would give zero correction here. Real GPTQ uses related inverse-Hessian information for many remaining coordinates. Inactive columns make the full four-feature Gram matrix singular, which is why we explicitly restrict this illustration to two active features.

The horizontal and vertical axes are candidate values of the two weights, not input features. Grid dots are allowed quantized pairs. Ellipses connect pairs with the same output SSE around the original pair [.49,.40]. Their tilted long direction permits opposing changes in the two weights to partly cancel on correlated inputs. Independent rounding chooses the nearest coordinate-wise grid point [0,0]; sequential compensation instead reaches [0,1], which lies on a lower output-error contour. The intermediate [.0,.645] is not yet a fully quantized pair. This geometric construction explains the two-coordinate update; it is not a claim that GPTQ exhaustively searches the integer lattice or reaches its global optimum.

Required checkpoint: explain what AWQ changes before rounding, what GPTQ changes after rounding one weight, why inputs matter, and why neither ensures task accuracy. Full implementations and derivations are optional; understanding these mechanisms is not.

5. NF4, selection algorithms and kernels are different layers

LayerQuestionExamples
RepresentationWhat does a four-bit code mean?Uniform INT4 grid; nonuniform NF4 table
SelectionHow are codes and scales chosen?Range + rounding; AWQ scaling; GPTQ compensation
ExecutionHow are packed values consumed?bitsandbytes kernels on the recorded T4

NF4 has sixteen nonuniform reconstruction levels designed around a normal-distribution assumption. A four-bit value indexes the table; block normalization and metadata reconstruct the weight. It is not integer rounding times one uniform step. The pinned table has adjacent positive levels near .07958 and .16093: normalized .12 is slightly closer to .07958. This lookup says nothing about speed or task accuracy. See the pinned codebook.

The sixteen ticks mark reconstruction values, not interval boundaries. Nearest-level decision boundaries lie midway between neighboring values. The normal curve is deliberately illustrative, not an estimated Qwen distribution. NF4 includes zero and its positive/negative values are not exactly symmetric. The comparison grid in the figure has sixteen equally spaced endpoint-inclusive values; it therefore has no exact zero. Our earlier symmetric integer toy uses fifteen levels and leaves one code unused. State the convention before comparing errors.

For each block, divide weights by their maximum absolute value, look up a nearby NF4 level, and multiply that level by the saved maximum when reconstructing. Thus .24 in a block of maximum 2 and .96 in a block of maximum 8 both normalize to .12 and select the same level, but restore to about .15916 and .63664. An all-zero block needs a safe zero reconstruction. The block maximum is not the uniform quantizer step. Normalization itself changes the observed distribution, so a normal-looking raw histogram does not prove NF4 is optimal for every block. Double quantization compresses scale metadata; it is a separate feature and is disabled in our experiment.

Our GPU experiment uses NF4 through bitsandbytes with FP16 computation and double quantization disabled. It runs neither AWQ nor GPTQ. The CPU lesson isolates numerical decisions; the A/B tests one real representation-plus-execution path. Restored floats in a list are not a compressed checkpoint, and multiplying them with an ordinary float operation does not benchmark a four-bit kernel.

Why not one quarter of all GPU memory? The pinned loader converts eligible linear layers, not every parameter. The capture counts 168 four-bit linear modules. Embeddings, excluded layers, scales, KV and temporaries remain. A peak counter does not break down their individual bytes. The layer API distinguishes storage and computation settings.

Allocated, reserved and device-wide memory

max_memory_allocated() measures PyTorch's peak live tensor allocation since its reset. max_memory_reserved() measures the peak memory held by its allocator, including reusable space. Neither counts every possible CUDA allocation or other process. In the pilot these peaks are reset before each timed generation; model weights are already loaded. Both lengths have already warmed up, so reserved pools can retain space from the longer condition. The 24/96 reserved counters are not independent fresh-memory experiments. See PyTorch 2.11's memory-management documentation.

Optional historical comparison: RTX 5070 Ti, 2 October 2026

A historical instructor capture on 2 October 2026 shows why the distinction matters. On an RTX 5070 Ti, FP16 allocated peak was 1,260,388,352 bytes and NF4 663,721,984 bytes: about 47.34% lower. Reserved peaks instead rose from 1,277,165,568 to 1,310,720,000 bytes, an increase of 32 MiB. These are measured historical counters, not expected pilot results.

The bounded conclusion is that this older run reduced its allocated peak but not its reserved peak. It did not show that twice as many requests would fit. KV cache, temporary tensors and runtime state remain separate costs. A capacity claim needs a workload-shaped service experiment, beyond this pilot. The older capture also used a different prompt set and measurement protocol; do not compare its timings with your pilot as a controlled speedup.

Equal work and an explicit clock

GPU launches are asynchronous. A CPU timer without the intended synchronization may mostly time enqueueing. The pilot synchronizes before and after generate; the interval includes host dispatch but excludes tokenization, input transfer, loading and warmup. It is not HTTP latency. Keep the five raw times for each condition, then compute the median and range; this small sample does not establish a stable production p95.

For matching work, divide baseline median wall time by candidate median wall time: a ratio above one favors the candidate. That is a ratio of medians, not a median of paired ratios. If format order or drift could explain a small difference, report the winner as unresolved. Changing 24 to 96 does not require wall time to become exactly four times larger: prompt processing is paid once and later decode steps need not all cost the same.

More dependent steps and retained KV can change the cost mix. A changed ordering is an observation; a claim that dequantization caused it is a hypothesis until supported. Inclusive profiler operator totals may overlap and are not measured memory-bandwidth counters. A profile recorded separately must not replace the uninstrumented timed trials.

Reveal nine answers and their limits
  1. Derive the scale. Maximum magnitude 7 divided by positive endpoint 7 gives scale 1; .49 rounds to zero. The counterfactual maximum is 1.40, scale .20, and .49 restores to .40. This changes the model; it only diagnoses the outlier effect.
  2. Compare groups. Scale .49/7=.07; codes [7,6] restore approximately [.49,.42]. The next pair [.60,7] still has step 1, so .60 restores to 1. Grouping isolates the outlier from some weights, not all.
  3. Transfer inputs. Errors are [−.89,−.09], [−.40,−.40] and [−4.90,+3.50]. Weight MSE stays .122825. Input magnitudes and cancellation change how weight errors affect outputs.
  4. Count metadata. Four code bytes plus 2/4/8/16 scale bytes gives 6/8/12/20, versus FP16 16. Information moved into metadata. Arithmetic omits FP16 scale-rounding; these counts omit headers and alignment.
  5. Explain scaling. Inverse scaling preserves the float layer before quantization. Rounding breaks the equivalence. Excessive scaling changes the shared grid: here factor 32 raises the step to 2.24 and harms other channels. Choose using calibration; evaluate separately.
  6. Prefer output preservation. Minimize (−.49+a)²+a²: a=.49/2=.245. The remaining .40 becomes .645 and rounds to 1. Weight SSE rises .4001→.6001; output SSE falls .9521→.3721. They optimize different things. The second sample worsens from .40 to .60 absolute error.
  7. Reject a confounded comparison. You measured different amounts of work, so this does not establish a slower execution path. Keep the natural answers for output-contract checks. Rerun both timing paths with the same input IDs and fixed output count, warmed up and synchronized, keeping every trial and failure.
  8. Transfer from 24 to 96 output IDs. It does not guarantee the ordering. More dependent decode steps and retained KV change the cost mix; setup is amortized differently. Fix model/tokenizer revision, prompt IDs, batch one, stack, decoding and format settings. Change only the fixed output count to 96 in both formats. Compare the new raw trials; do not substitute a new GPU or a new prompt.

Lower allocated bytes alone do not establish usable capacity. Optional reading, not another required syllabus

For the full algorithms beyond the required mechanisms, AWQ and GPTQ provide different approaches. Full implementations and derivations, FP8/NVFP4 and custom CUDA kernels are optional; AWQ/GPTQ mechanisms are mandatory.

The experiment-first structure borrows the controlled-ablation approach of MIT EfficientML Lab 4: change a mechanism, compare with a control, explain the result. That lab's pseudo-quantization does not itself demonstrate packed-kernel speed. The small implementation with explicit tests follows the incremental-code pattern of CMU Deep Learning Systems HW0. Our workload, hardware results and acceptance contract are our own, not copied benchmark claims.
