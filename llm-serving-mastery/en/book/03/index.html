The actual request and the decision

The deployment question is often phrased as “Can we switch to four bits?” A useful version names an objective: can this exact candidate preserve the output contract and improve usable capacity or latency on this GPU? The candidate includes a model revision, tokenizer, quantizer configuration, checkpoint layout, runtime, kernel path and workload. A bit width identifies only part of that object. Lower checkpoint bytes, lower peak live allocation, lower allocator reservation, lower latency and better service capacity are distinct hypotheses.

Our current anchor is the 2 October instructor capture on Qwen2.5-0.5B-Instruct revision 7ae557604adf67be50417f59c2c2f167def9a775, from clean source 7c23155. It used an RTX 5070 Ti, Transformers 4.51.3, bitsandbytes 0.50.2 and Torch 2.14.0+cu130. The earlier 29 September smoke remains a separate historical observation. One current prompt asks:

Reply with exactly one word: blue or orange. What color is the sky on a clear day?

The tokenizer's chat template made this 49 input tokens. The recorded natural-EOS FP16 answer was blue; NF4 produced Blue.. We did not infer these strings from a score or replace them with a convenient “correct answer” box. The current capture retains every input and output ID, exact rendered chat, token pieces and stop reason. These details were measured in the new run; they are not retroactively attached to historical timings.

For a client that accepts exactly blue or orange, the second string fails. For a semantic color question, both answers identify the same color. That distinction is a product contract, not an argument about whether a period is “important.” The exact-string check is an explicit teaching interpretation; four prompts do not establish a population-level quality regression. The current experiment also observed lower allocated memory and mixed prompt-level timing comparisons. We will explain the measurements without pretending they establish the responsible kernel.

Keep three evidence layers separate while reading. Dated GPU captures are measured behavior of a pinned real model. The tiny CPU example below uses invented weights so every intermediate fits on a page. AWQ/GPTQ examples explain local mechanisms from primary sources but do not reproduce those full algorithms. No latency belongs to the toy, and the NF4 smoke is not an AWQ benchmark.

A scalar quantizer as an executable contract

A code is a small integer or lookup-table index. A reconstruction rule maps it back to a numerical value. Uniform affine quantization uses a positive scale s and an integer zero point z. In this chapter's general integer map, q = clip(roundEven(w/s) + z, −8, 7) and ŵ = s(q−z). The input w and reconstructed ŵ have weight units. Scale has weight units per code. The division produces a dimensionless number, and the stored code is dimensionless.

Our main fixture chooses s=0.25, z=0, and signed four-bit codes −8…7. Zero point zero makes the map symmetric around real zero in its offset, although the two's-complement range has an extra negative endpoint. Some schemes deliberately use −7…7 instead. Those are different contracts. We state the range rather than silently switching between them. The full generated CPU fixture records every stage and the rounding policy.

For w=1.83, dividing by 0.25 gives 7.32. Nearest-integer rounding gives 7, clipping leaves 7, and reconstruction gives 1.75. Signed error, consistently defined here as ŵ−w, is −0.08. For w=2.25, division gives 9, rounding leaves 9, clipping changes it to 7, and reconstruction again gives 1.75. Its error is −0.50. Both values end at the same stored code, so decoding cannot recover their former separation.

Rounding within an unclipped uniform grid limits absolute error to half a step, here 0.125. Saturation invalidates that bound. A larger scale can cover larger magnitudes, but moves neighboring reconstruction levels farther apart. A smaller scale can resolve common small weights while clipping more extremes. The tradeoff cannot be decided from bit width alone. Notice the subtle first example: 1.83 exceeds the largest reconstruction 1.75, yet its rounded integer already equals 7. The clip operation itself changes nothing in that case.

Halfway values and zero points

Nearest rounding still needs a tie rule. The fixture uses ties-to-even: 2.5 maps to 2, 1.5 to 2, −1.5 to −2 and −2.5 to −2. At scale 0.25, input 0.625 therefore reconstructs as 0.5, not 0.75. Choosing a language's default rounding function without checking its negative and halfway behavior can make a CPU replay disagree with another implementation. The notebook and interactive quantizer use the declared rule. Tests include both positive and negative ties.

An affine zero point shifts which code represents zero. With s=0.2,z=−2, real zero maps to code −2. Input 0.6 first rounds to 3, then adding −2 yields code 1. Reconstruction is 0.2×(1−(−2))=0.6. Actual binary floating-point may retain an error near machine precision; that is distinct from a deliberate coarse reconstruction. A correct loader must preserve the zero point as well as scale, range, shape and code ordering.

From signed codes to bytes and back

Four bits hold one of sixteen patterns, but ordinary memory addresses bytes. The teaching format packs two codes per byte. It uses four-bit two's-complement encoding and stores the earlier code in the low nibble. A nibble is four bits. The signed code −7 has pattern 1001, and −2 has 1110. Their combined byte is 1110 1001, hexadecimal E9. Hexadecimal writes each nibble as one digit, with A through F representing ten through fifteen.

The executable packing expression is (q0 & 15) | ((q1 & 15) << 4). The bitwise AND selects each four-bit pattern, the shift moves the second into the high nibble, and OR combines the disjoint fields. The next pair, codes 1 and 7, becomes 71. The main eight-weight fixture occupies four code bytes: e9 71 c1 84. Its shape and scale still need storage. This intentionally simple layout is not a claim about bitsandbytes NF4, GPTQ or AWQ packing.

Unpacking reverses each operation. Read the low nibble with byte & 15 and the high nibble with byte >> 4. Values 8…15 represent negatives: subtract sixteen. For E9, unsigned nibbles 9 and 14 become −7 and −2, then scale 0.25 yields −1.75 and −0.5. If a reader interprets them as unsigned, reverses their order or attaches the next group's scale, every later matrix operation receives the wrong values. A file can have the expected size and still be numerically invalid.

Real kernels often pack values in tile-oriented orders for vectorized memory access. They can pad rows or groups and interleave metadata. That is why loader support and a model's format name do not establish compatibility with an arbitrary optimized kernel. The actual layout, group size, scale representation and device capability must agree.

A model contains many layers, nonlinearities, normalization, residual additions and a final vocabulary choice. Local errors can cancel, amplify or move a close logit ordering. A low weight mean-square error therefore does not guarantee the same generated text. Conversely, different text can remain task-correct. We use layer arithmetic to explain a mechanism and task-level evaluation to assess its consequence.

Which errors matter depends on the input

Keep the first row of weights fixed. Input [1,0,0,0] creates output error +0.08. Input [0,0,0,10] creates −5.0. The weight errors did not change; the activations selected and amplified different coordinates. This is the motivation for inspecting representative activation distributions when designing a quantizer. It is also why “protect the largest weights” is not equivalent to “protect the most consequential channels.” A channel means a feature coordinate across many input positions.

Scale granularity determines which values share one mapping. A per-tensor scale covers an entire tensor. A per-channel scale follows one declared axis. Group-wise scales cover smaller fixed sets, frequently along input-feature blocks, but the exact axis and layout belong in the artifact contract. Smaller groups can prevent a remote outlier from setting a coarse step for unrelated small weights. They add metadata and can constrain available kernels.

For the eight-value vector [−0.1,0.2,−0.3,0.4,8,9,10,11], choose the explicitly different scale policy absmax/7. One global scale is 11/7≈1.5714. Each of the first four scaled magnitudes is below 0.5, so all four round to zero. Split into two groups of four and the first scale becomes 0.4/7≈0.05714. Its codes are [−2,4,−5,7], reconstructing approximately [−0.114286,0.228571,−0.285714,0.4]. The second group's scale remains 11/7. This absmax/7 policy leaves code −8 unused; it does not redefine the main fixed-scale toy.

Clipping objectives introduce another choice. Covering every extreme can waste resolution on rare magnitudes. Allowing some clipping can lower error on the common distribution but hurt a critical task. The correct decision needs both a calibration objective and held-out tasks that reflect consequential failures. An outlier is a value relative to a distribution or scale-sharing group, not a universal numerical threshold.

Weights, activations and KV have different lifetimes

Weights persist across requests and participate in dense projections. Activations change with the current input and forward step. KV cache stores past keys and values for a particular live sequence so later attention can reuse history. Compressing one does not automatically compress the others. W4A16 denotes four-bit weight representation and sixteen-bit activations; it does not specify KV precision, every accumulator dtype, or whether a kernel reconstructs a full tensor or only a tile.

A fused weight-only path can load packed weight codes and scales, reconstruct a tile inside the compute kernel and multiply it with higher-precision activations. A less efficient path may materialize a temporary reconstructed buffer, make extra memory passes or launch more kernels. Both can honestly store four-bit weights. This is one plausible explanation for a slower low-bit candidate, but the historical smoke has no operator trace to prove that explanation. A profile must show what executed.

W8A8 changes both operands. In a simple zero-point-zero dot product, integer code products accumulate before multiplication by the scale product. With weight codes [2,−3], activation codes [4,5] and scales 0.1 and 0.2, the integer dot is −7. Multiplying by 0.02 gives −0.14, the same as the reconstructed float dot 0.2×0.8−0.3×1.0. Nonzero zero points require offsets in the multiplication. Per-channel or per-token scales also change where factors apply. Actual accumulator range and saturation remain kernel-specific.

KV quantization changes retained request state. The logical formula is 2×L×Hkv×dh×bKV×T bytes: two tensors, layers, KV heads, head width, bytes per element and total retained token positions. Topic 02's 3B transfer example uses 36 layers, two KV heads, width 128 and 49,152 positions. At two bytes per element this is exactly 1.6875 GiB. One byte per element would halve that logical term before scales and block overhead. Four-bit weights alone leave it unchanged. KV precision needs a supported attention implementation and long-context quality checks because the altered history is reused repeatedly.

NF4 is a lookup table, not uniform signed INT4

QLoRA introduced NormalFloat4 for a weight-distribution setting. An NF4 code selects one of sixteen nonuniform values; block scaling maps the normalized value to the original range. It has no sign/exponent/mantissa interpretation like a tiny floating-point format. The actual bitsandbytes 0.50.2 implementation supplies the table used in the notebook's lookup illustration.

Double quantization compresses some quantization constants themselves. For a hypothetical 1024-weight block collection with sixteen FP32 absmax values, code bytes consume 512 bytes and those scales consume 64 bytes. Sixteen eight-bit scale codes would use 16 bytes, but need second-level metadata to reconstruct the scales. The net saving is therefore smaller than the raw 48-byte difference. A reconstructed scale adds another source of weight error. Inspect actual state instead of assuming that a four-bit label or a double-quantization flag determines an exact process footprint.

FP8 and NVFP4 represent different numerical schemes. FP8 E4M3 and E5M2 allocate exponent and fraction bits differently, so equal storage does not imply equal range or resolution. NVIDIA's TensorRT quantization definitions describe NVFP4 with E2M1 values, fine block scaling and a higher-level scale. None of those names establishes native acceleration on an arbitrary GPU. Match the installed engine release, exact type, scale hierarchy and device support before extrapolating performance. The lab executes bitsandbytes NF4, not every format in this section.

Why AWQ and GPTQ need more than nearest rounding

Post-training quantization starts from trained weights. Quantization-aware training exposes weights to quantization effects during training or fine-tuning. These are workflow categories, not storage types. A PTQ method may use calibration activations or merely weight statistics, depending on the method. The lab's NF4 loading does not run AWQ calibration, GPTQ optimization or QAT. Their mechanisms are studied here so students can interpret a candidate's provenance and know which empirical claim remains untested.

AWQ: an equivalent channel scaling

AWQ uses activation information to search channel scales that protect consequential weight contributions without retaining a scattered high-precision subset. If S is invertible and diagonal, Wx=(WS)(S⁻¹x). Float arithmetic preserves this product, while quantization can change the error because it sees scaled weights.

Our local example has W=[0.13,2] and x=[10,1], product 3.3. Scaling the first weight channel by four gives [0.52,2], while the inverse-scaled input is [2.5,1], still product 3.3. For this example only, use step 0.25 and a code range wide enough to retain value 2. Unscaled rounding gives [0.25,2] and output 4.5; scaled rounding gives [0.5,2] and output 3.25. Errors are +1.2 and −0.05. The fixed step isolates the mechanism. A real group scale may move when a channel grows, damaging other channels. AWQ searches with calibration data rather than assuming every larger scale helps.

GPTQ: compensate in remaining weight directions

GPTQ uses approximate second-order information to reduce layer-output reconstruction error. With calibration input matrix X, the local objective compares WX with ŴX. Input correlations mean independent rounding need not minimize that objective. Quantizing one part can be followed by a compensating update to weights not yet fixed. Damping and efficient block updates matter in the full method.

Take one invented calibration vector [1,1] and weights [0.6,0.6]. Reference output is 1.2. Independent unit-step rounding gives [1,1], output 2 and error +0.8. After fixing the first weight to 1, setting the remaining unfixed weight to 0.2 preserves 1.2 before its own quantization. Rounding that remainder to zero gives [1,0], output 1 and error −0.2. The local absolute error improved, but a new input [0,1] reverses the advantage: errors become +0.4 and −0.6. The example demonstrates compensation and its limits, not a complete GPTQ solve.

The single-row Gram matrix in that illustration is singular. Real implementations collect more activation vectors and regularize poorly conditioned directions. The original implementation exposes the damped inverse/Cholesky machinery and sequential updates. A calibration-set reconstruction improvement must still survive held-out model-quality evaluation and the target packed kernel.

Calibration data choose a representation. Held-out prompts evaluate a frozen candidate. A canary observes behavior under actual service traffic after the gate. Mixing these roles can conceal overfitting. Code, arithmetic, long contexts and language buckets may exercise different activation ranges, but the evaluation set must not become an unlimited tuning set. Private course judge data are never a calibration corpus.

A complete byte budget

For a hypothetical three-billion-parameter model, sixteen-bit codes occupy 3×10⁹×16/8=6×10⁹ bytes. Four-bit codes occupy 1.5 billion bytes. Decimal GB means 10⁹ bytes; binary GiB means 2³⁰ bytes. The two payloads are approximately 5.588 and 1.397 GiB. The exact four-to-one ratio applies to those code terms only, not to model files, allocator reservation or system-wide occupancy.

If one FP16 scale serves each group of 128 weights, the group count is ceil(N/128). Here three billion divides evenly, yielding 23,437,500 scales, or 46.875 million bytes. Codes plus scales total 1.546875 GB, approximately 1.441 GiB. Effective storage becomes 4+16/128=4.125 bits per weight under this very specific scheme. Zero points, padding, nested metadata and modules kept at higher precision add terms.

For a small visible comparison, 1024 four-bit weights always require 512 raw code bytes. Groups of 128 add sixteen scale bytes, while groups of 32 add sixty-four. Smaller groups can reduce error and increase storage simultaneously. If a format pads 130 values to two full 128-value groups, its code payload is 128 bytes rather than the raw 65, plus scale state. This padding rule is illustrative; another kernel might handle a partial tail. The artifact and kernel decide, not the name INT4.

Unquantized embeddings, output heads, normalization and sensitive projections can alter the model census, depending on the scheme. Tied weights also affect whether a parameter is stored once or twice. A real count should inspect the actual loaded state and quantization configuration. The serving process adds KV, activations, workspaces, kernel/runtime allocations and allocator pools. Each term has a lifetime and a measurement boundary.

An illustrative 16 GiB GPU budget with 2 GiB reserved for runtime and 1.69 GiB logical KV leaves 12.31 GiB before weights. Subtracting the hypothetical 5.588 GiB FP16 weight payload leaves about 6.722 GiB; the four-bit-plus-scales toy leaves about 10.869 GiB. Both fit this simplified budget. Quantization therefore needs an additional objective such as longer contexts, more simultaneous sequences or a larger model, and must earn any quality or latency cost. These allowances are not measured safety margins for the course machine.

What the current FP16/NF4 run actually observed

The 2 October experiment held model revision, tokenizer, prompt set, hardware and greedy decoding constant. It loaded FP16 and NF4 separately. Each format retained four natural-EOS quality answers and twelve fixed-24-token timing continuations, three trials per prompt. That is 32 retained samples, excluding the two warmup calls, not 32 independent quality examples. The current record contains all outputs, IDs and trial arrays. It does not contain a full operator profile, a production arrival process or a held-out population-quality evaluation.

Exact allocated peaks were 1,260,388,352 and 663,721,984 bytes. The relative reduction is approximately 47.34%. Exact reserved peaks were 1,277,165,568 and 1,310,720,000 bytes, an increase of 33,554,432 bytes, exactly 0.03125 GiB. Rounded slide numbers are convenient for discussion; calculate percentages from original bytes. PyTorch allocated tracks live tensor allocation, while reserved includes the allocator's reusable pool. Device-wide occupancy can include other allocations and processes.

Neither counter proves that a deployed API has gained capacity for more live requests. An actual service may preallocate KV, keep workspaces, change batch shapes or fragment allocations. The instrumented smoke's peak boundary also differs from an uninstrumented steady-state load study. Use the counters to reject the vague sentence “four bits used half the GPU,” then design the missing service-capacity measurement.

A repeat is useful even when it changes the story

The 29 September record had FP16 per-prompt maxima of 0.54–0.81 seconds and NF4 maxima of 1.05–1.28 seconds, so NF4 was slower on all four probes in that run. Its color FP16 trials were 0.554258, 0.502291 and 0.540703 seconds, the numbers used by exercise 22. In the current capture, the arithmetic ordering reverses. Preserve both and investigate variance instead of selecting whichever run supports a preferred format.

The local generation TTFT clock ends at the first selected output-ID callback, not at first nonempty client text over a network. A post-first proxy divides the interval from that callback to generation return by the remaining selected IDs, including return overhead. It is neither a CUDA-only interval nor a measured distribution of individual token gaps. API TTFT can include queueing, serialization and transport, while streaming chunks need not match tokens. Preserve clock definitions when moving to Topic 04; a local generation measurement cannot be relabeled a service SLO.

A speed model that makes a testable prediction

Suppose a decode step actually transfers 6 GB of weights at effective 300 GB/s. The transfer alone takes 20 ms. A candidate transferring 1.55 GB and adding 2 ms of conversion work takes about 7.17 ms in a serial additive toy. The break-even added work is (6−1.55)/300≈0.01483 seconds. These are assumptions, not measurements of the RTX 5070 Ti. Actual overlap, matrix arithmetic and traffic can invalidate the model.

More token rows can reuse one weight tile. A 1536×1536 projection performs approximately 4.72 million floating-point operations per row if a multiply and add count as two. Forty-two prefill rows perform about 198.18 million operations with the same weight matrix, assuming ideal reuse. At high reuse, compute and conversion efficiency can matter more than the nominal file compression ratio. At long contexts, KV reads can matter more. A format that helps one phase or batch can hurt another.

A useful profile distinguishes hypotheses. Additional dequantization kernels and large temporary buffers would support a materialized reconstruction explanation. A small number of inefficient matrix kernels would point toward a shape/backend issue. Long host gaps would suggest launch or control overhead. Instrumentation perturbs execution, so use a short focused trace for attribution and repeat uninstrumented measurements for reported performance. Do not keep adding full GPU benchmark runs while the question is only which operator executed.

A paired quality study begins with a declared rule

Freeze prompts, tokenizer, model identity, decoding policy and scoring rules before examining candidate outputs. Use exact matching when the downstream contract is exact, parsers and schema validators for structured data, executable tests for code where appropriate, and a blinded rubric for subjective answers. Invalid, truncated, timed-out and errored attempts stay visible. Removing them from the denominator can make a failing candidate look better. A strict hard gate and a statistical average-quality margin answer different questions.

In a constructed 200-prompt table, 160 pass both candidates, ten pass only baseline, four pass only candidate and 26 fail both. Baseline succeeds on 170 and candidate on 164, a difference of −3 percentage points. Fourteen pairs changed outcome, not six. Reporting only 85% and 82% erases which tasks regressed and how strongly the pair outcomes correlate. A paired bootstrap resamples complete prompt pairs rather than unrelated baseline and candidate rows. A meaningful interval needs enough data and a sampling design appropriate to the deployment population.

Bucket-level severity also matters. Ten losses concentrated in a billing schema can be unacceptable even if another bucket gains more successes. A small semantic average change can hide a doubled parse-failure count. Conversely, a four-prompt smoke deliberately containing tricky formatting constraints cannot estimate how common that failure is among users. The small smoke discovers defects and verifies execution. It does not certify a one-point non-inferiority margin.

A conditional deployment memo

Retaining the validated FP16 default is defensible while evidence remains incomplete. NF4 reduced allocated bytes, but not the reserved peak. Its current prompt-level timing comparisons are mixed, and the repeated smoke does not establish a stable speed winner. The color pair warrants a strict-format investigation. This conclusion is conditional on the exact model, runtime and workload. A larger model, different kernel, greater batch or genuinely binding memory constraint can justify reopening the decision.

A release memo should say what evidence would change the answer. First verify compatibility of the exact artifact and target kernel. Then measure full-service peak memory and workload-shaped latency, including failures. Use a representative held-out paired quality set with hard gates and uncertainty. Define a rollback trigger before a canary. A candidate that violates a hard output contract does not become acceptable because its average tokens per second is larger.

Keep teaching evidence separate from grading thresholds. This chapter does not change a judge reference, a quality floor or a hidden workload. A quantized candidate that looks promising in a notebook cannot silently replace the course baseline. The student deliverable is the experiment and defensible decision, including unresolved causes, rather than a required declaration that NF4 wins.

Lab: exact CPU arithmetic first, bounded GPU work second

The standalone notebook starts with a standard-library CPU replay: scalar stages, rounding ties, packing round trips, complete matrix outputs, group scales and the NF4 table illustration. It reads no model weights and requires no CUDA installation. Change one toy value, predict the affected code and output, then execute the check. Preserve the distinction between a deterministic arithmetic assertion and empirical model behavior. Passing the CPU section does not replace the required CUDA smoke.

For GPU work, reuse the persistent pinned local snapshot and matching environment. Load one format at a time. Begin with startup and one short request, check available RAM, device use and cleanup, then proceed only within the documented limits. Preserve raw per-trial rows before summarizing. Stop on allocation growth, an unexpected failure, an incomplete artifact or memory that does not recover to the declared baseline. Do not repeatedly download weights or create a second concurrent GPU process to make progress faster.

The comparison artifact must retain candidate identity, prompt set, literal outputs, token counts, natural versus forced stopping mode, raw timing arrays, clock definitions, peak allocated/reserved bytes and limitations. The decision memo accompanies a hand budget, paired output annotations and a falsifiable follow-up. It should state whether the result is reproduced locally or only replayed from a supplied dated capture. Neither a green import nor an output-free notebook proves the GPU branch ran.

Terms used in this chapter

Quantization
Mapping numerical values to a restricted representation with an explicit reconstruction rule.
Code and codebook
A stored small integer or index, and the set of values to which codes reconstruct. A nonlinear codebook need not have equal spacing.
Scale and zero point
The multiplier that converts code units to value units, and the integer code representing real zero in an affine map.
Clipping or saturation
Replacing a rounded code outside the allowed interval with its nearest allowed endpoint.
Rounding ties-to-even
Choosing the nearest integer and, at an exact half-integer, the even neighbor.
Nibble and packing
A four-bit field, and a layout that combines fields into physical bytes or larger kernel-oriented units.
Group size
The number of values sharing quantizer metadata. The grouping axis and padding policy are also part of the format.
Activation
A value computed for the current input. Activation statistics reveal which weight directions contribute to layer outputs.
Calibration
Using designated data or statistics to select quantizer parameters. It is distinct from held-out evaluation.
PTQ and QAT
Post-training quantization and quantization-aware training, two workflows for choosing or adapting a model under reduced precision.
W4A16 and W8A8
Labels for weight and activation representation widths. They do not by themselves specify KV precision, accumulation or the exact kernel.
NF4 and double quantization
A nonuniform four-bit lookup representation and a scheme that also compresses some quantization constants.
Allocated and reserved memory
Live tensor allocation tracked by PyTorch and the wider pool its allocator holds. Neither equals every possible device allocation.
Discordant pair
A prompt for which baseline and candidate have different scored outcomes. Regressions and improvements form separate directions.
Goodput
Useful successful output per wall-time unit under declared correctness and latency constraints, rather than all generated tokens regardless of validity.

Predictions about unobserved kernels or other GPUs must remain hypotheses. The answers distinguish a calculation from a deployment conclusion.

  1. Scalar reconstruction. At scale 0.25 with signed codes −8…7, find the scaled value, rounded integer, clipped code, reconstruction and signed error for 1.83 and 2.25.
  2. The negative endpoint. Quantize −2.40 under the same rule. Why is the reconstruction −2.00 rather than −1.75?
  3. A halfway input. Quantize 0.625 with scale 0.25. Which result changes under ties-away-from-zero?
  4. Affine zero point. Let s = 0.2 and z = −2. Which code represents real zero? Quantize 0.6 and reconstruct it.
  5. Nibble packing. Encode [−7, −2, 1, 7] as low-nibble-first signed INT4. Decode your bytes independently.
  6. Packing failure. A reader treats E9 as high-nibble-first unsigned codes. What first two weights would it reconstruct at scale 0.25?
  7. Complete projection. Recompute both outputs of the tiny 2 × 4 projection before and after quantization.
  8. Error decomposition. For output 0, multiply each weight error by the corresponding activation and sum the four terms.
  9. Activation shift. Use [0, 0, 0, 10] with the same first weight row. How large is the output error?
  10. Grouped outliers. Why do the first four values of [−0.1, 0.2, −0.3, 0.4, 8, 9, 10, 11] vanish with a single absmax/7 scale?
  11. Scale bytes. For 1024 four-bit weights, compare groups 128 and 32, with one FP16 scale each and no padding.
  12. Partial groups. A layout pads 130 weights to two full 128-value groups. Count code and scale bytes.
  13. NF4 lookup. For block absmax 2 and w = 0.5, use c₁₀ ≈ 0.2461123. What are the normalized input and reconstructed weight?
  14. Nested scales. If sixteen FP32 scales become sixteen eight-bit codes, how many scale-code bytes disappear before second-level metadata?
  15. AWQ equivalence. Show that [0.13, 2] · [10, 1] = [0.52, 2] · [2.5, 1]. Does that prove the quantized result is equal too?
  16. Compensation limits. For calibration x = [1, 1], compare independently rounded [1, 1] with compensated [1, 0] against original w = [0.6, 0.6]. Then test x = [0, 1].
  17. W8A8 arithmetic. Compute the reconstructed dot product for codes qW = [2, −3], qA = [4, 5], scales 0.1 and 0.2 with zero points 0.
  18. Weight and KV budgets. Does changing only weight storage from 16 to 4 bits halve a 1.6875 GiB FP16 KV payload?
  19. Allocator boundary. Use the exact current byte counters to calculate the relative allocated reduction and reserved change.
  20. Strict versus semantic scoring. How should blue and Blue. score if a client accepts only the exact strings blue or orange? What changes under semantic color scoring?
  21. Forced continuation. Why must the fixed-24-token arithmetic output not replace the natural-EOS quality answer 45?
  22. Three-trial p95. Sort the historical 29 September FP16 color-prompt wall times and locate nearest-rank p95. Is it a loaded API SLO?
  23. Discordant pairs. For 160 pass-both, 10 baseline-only, 4 candidate-only and 26 fail-both prompts, compute the quality delta and discordance count.
  24. A deployment memo. Would you make current NF4 the default for this 0.5B path today? Give one reason to reopen the decision and one bounded next measurement.
Check all 24 answers and their limits
  1. Scalar reconstruction. For 1.83: 7.32 → 7 → 7 → 1.75, error −0.08. For 2.25: 9 → 9 → 7 → 1.75, error −0.50. Only the second integer changes in the clip operation.
  2. The negative endpoint. −2.40/0.25 = −9.6, rounded −10, clipped −8, reconstructed −2.00. Two’s-complement signed INT4 has an extra negative code. Error is +0.40. A narrow symmetric −7…7 design would be a different contract.
  3. A halfway input. The scaled input is 2.5. Ties-to-even gives code 2 and 0.5. Ties-away-from-zero gives code 3 and 0.75. Both have absolute error 0.125, but different signed errors.
  4. Affine zero point. Zero maps to −2. The 0.6 input rounds to 3 before adding z, so q = 1. Reconstruction 0.2 × (1 − (−2)) = 0.6, up to floating-point arithmetic.
  5. Nibble packing. Nibbles are 9, E, 1, 7, giving bytes E9 and 71. Decode low then high: 9 → −7, E → −2, 1 → 1, 7 → 7. Multiplying by 0.25 gives [−1.75, −0.5, 0.25, 1.75].
  6. Packing failure. It reads 14 and 9, reconstructing 3.5 and 2.25 instead of −1.75 and −0.5. Bit count alone cannot specify a valid checkpoint. Both order and signed interpretation are wrong.
  7. Complete projection. Original outputs [2.705, −1.15], reconstructed [2.0, −0.25]. The difference is [−0.705, +0.9]. Keep the [out, in] convention consistent instead of silently transposing W.
  8. Error decomposition. ΔW₀ = [0.08, 0.02, 0.01, −0.50]; products are [0.08, −0.04, 0.005, −0.75], summing −0.705. The clipped fourth feature dominates this particular input.
  9. Activation shift. Only the fourth weight matters: −0.50 × 10 = −5.0. This does not change weight MSE at all. It changes the input distribution against which that MSE must be interpreted.
  10. Grouped outliers. Scale 11/7 ≈ 1.5714 makes their scaled magnitudes below 0.5, so every code rounds to zero. A separate first-group scale 0.4/7 preserves their distinctions, at the cost of another scale.
  11. Scale bytes. Code bytes 512 for both. Group 128 adds 8 × 2 = 16 bytes, total 528. Group 32 adds 32 × 2 = 64 bytes, total 576. This counts a hypothetical metadata scheme, not actual NF4 state.
  12. Partial groups. 256 padded codes use 128 bytes; two FP16 scales add 4 bytes, total 132. Raw 130-code payload would be 65 bytes. The padding rule must be explicit.
  13. NF4 lookup. Normalized 0.25 selects index 10 in the nearest-level illustration. Reconstruction ≈ 0.4922246, signed error ≈ −0.0077754. Index 10 is a table address, not a signed linear integer code.
  14. Nested scales. 64 − 16 = 48 bytes. That is an upper saving before offsets, second-level scales, shape and other metadata. Double quantization can add error in the reconstructed scales.
  15. AWQ equivalence. Both float products equal 3.3. The inverse scaling cancels before quantization. A nonlinear rounding operation breaks the cancellation: with step 0.25 the reconstructed results are 4.5 and 3.25. Real scale search must consider all affected channels.
  16. Compensation limits. Calibration errors are +0.8 and −0.2. On [0, 1], original 0.6 becomes 1 or 0, errors +0.4 and −0.6. The calibration improvement reverses on this new input. A single-row example is not a GPTQ quality guarantee.
  17. W8A8 arithmetic. Integer accumulation 2 × 4 − 3 × 5 = −7. Multiply by 0.1 × 0.2 to obtain −0.14. The accumulator and saturation behavior remain runtime-contract questions.
  18. Weight and KV budgets. No. That payload stays 1.6875 GiB. A separately supported one-byte KV format would make the logical term 0.84375 GiB before scale and block overhead, and requires its own quality validation.
  19. Allocator boundary. Allocated reduction is (1,260,388,352 − 663,721,984) / 1,260,388,352 ≈ 47.34%. Reserved rises 33,554,432 bytes, exactly 0.03125 GiB. Rounded displayed GiB values produce slightly different percentages. Neither result proves half the device is free.
  20. Strict versus semantic scoring. Only blue passes the exact-string validator; both identify the same color. The declared downstream contract chooses the rule. This observed pair is insufficient to estimate a population-level NF4 regression rate.
  21. Forced continuation. The timing branch intentionally continues past natural stopping so work length is controlled. It answers a performance question under forced work. Treating that continuation as the natural answer changes the experiment and can misattribute failures.
  22. Three-trial p95. Sorted 0.502291, 0.540703, 0.554258 seconds. ceil(0.95 × 3) = 3, selecting the maximum 0.554258 seconds. This tiny sequential sample has neither reliable tail estimation nor concurrent-service scope.
  23. Discordant pairs. Baseline 170/200 = 85%; candidate 164/200 = 82%; delta −3 percentage points. Fourteen pairs change outcome, not six. Pair structure is necessary for uncertainty and bucket-level triage.
  24. A deployment memo. A justified hold cites no reserved-pool reduction, a strict-format warning and unresolved prompt-level timing differences. A changed model/workload/kernel may reopen it. Profile a short representative operation trace, then repeat uninstrumented paired trials with fixed workload, raw failures and memory-recovery checks. Do not claim the suspected dequantization cause is proven.
