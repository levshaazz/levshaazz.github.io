What the GPU computes for one request

Logical tensor shapes · pinned Qwen config
For one sequence with S rendered positions: input IDs [1,S], decoder hidden states [1,S,896], last-position vocabulary logits [1,151936]. Each layer retains K and V of logical shape [1,2,S,64]. Decode consumes one new position and appends one KV position. These are logical shapes, not a physical vLLM memory trace. 24 decoder layers. Prefill processes the prompt; each subsequent decode step adds a position. Serving may pack requests and page KV physically.

Temperature changes the next-token distribution

Invented logits [2, 1, 0] · nucleus mass = 1
Toy vocabulary tokens A,B,C have logits2,1,0. Probabilities at temperature0.5:0.8668,0.1173,0.0159; at1:0.6652,0.2447,0.0900; at2:0.5065,0.3072,0.1863. Greedy temperature0 selects A. These are invented next-token probabilities, not Qwen class confidence. For T>0 use softmax(z/T); T=0 selects argmax. Increasing temperature flattens this example without improving classification by itself.

Nucleus sampling keeps a cumulative prefix

Toy logits · T = 1 · p = 0.8
Descending A,B,C probabilities0.6652,0.2447,0.0900. A alone is below0.8; A+B reaches0.9100. Keep A and B, remove C. After renormalization probabilities0.7311,0.2689,0. Probability0.8 is a nucleus mass threshold, not a confidence cutoff for each token. Nucleus sampling changes the candidate set. It does not mean “accept a class if its probability is above 0.8.”

Constrained output controls syntax, not meaning

Prefix constraint · illustrative strings
Allowed complete strings are billing, access and bug. At string prefix b only billing and bug remain possible; at bi only billing remains. At the empty prefix access is also allowed. Token grammar handles multi-token names and termination; it is not a mask assuming one token per class. The versioned choice constraint limits whole strings. The constraint can prevent prose, but a wrong allowed label remains wrong. A tight output cap can still truncate.

Streaming

A partial answer is not a completed request.

Streaming improves when the client sees content, not merely when the server computes a token.

Nine text deltas form the recorded greeting

Fresh v3 capture · client-arrival clocks
For the literal prompt Say hello briefly. the recorded answer is Hello! How can I assist you today? Nine nonempty content events form that text. First content arrived at 58.722 milliseconds, finish stop at 173.543 milliseconds and DONE at 173.618 milliseconds. The capture has 13 byte reads, 13 data events, 12 JSON objects and 10 reported completion tokens. These distinct counts are not interchangeable. The full byte transcript is replayable without a server. This one sequential smoke does not estimate p95, concurrent capacity or GPU-only decode time. Output token IDs were not returned.

Finish, DONE and useful output are separate checks

Synthetic completion decisions
The application checks HTTP status, a valid data stream, generation finish reason and the terminal DONE marker. Finish stop plus DONE means protocol complete under this text-only course contract. Length plus DONE is complete transport with generation capped. A quality or format assertion can still fail. A text-only application may reject empty content. A general tool-calling client must use a different content contract. Terminal completion does not prove semantic quality.

Capacity

Context, live tokens and memory determine admission.

Limits shape a safe service; they do not promise throughput or p95 latency.

Rendered input and requested output share a context budget

Measured rejection + illustrative alternatives
A measured prompt2329 already exceeds the configured2048token context by281 and received400. An illustrative1800prompt with512output cap asks2312,264over; the same prompt with128output cap asks1928,120spare. These are arithmetic plans, not new API observations. Count rendered tokens, including template and history. Actual validation and generation-budget rules follow the pinned server. Characters and HTTP bytes use different units.

The lab model retains 12 KiB of logical KV per token

Pinned 0.5B config · payload arithmetic
Qwen2.5-0.5B has24layers,2KVheads and64values per head. At2bytes/value, keys and values require2×24×2×64×2=12288bytes per retained token. Four hypothetical2048token sequences require96MiB logical payload. Device allocation includes many other components. This is the actual lab architecture, unlike the separate 3B transfer exercise. A logical KV payload excludes weights, blocks, allocator reservation, workspaces and runtime overhead.

A sequence cap is not a performance guarantee

Common shortcut
Limit interpretation

“--max-num-seqs 4 guarantees four requests at any context.”

Token lengths, KV pages, model size and batch-token budget determine fit; queueing and kernel time determine latency. Measure the actual workload.
The lab caps active sequences at four to reduce risk, not to benchmark four concurrent clients.
