01 / 07

Map the number

Every saved bit introduces a reconstruction rule.

Start with one scalar; then expose why groups and kernels change the real model.

FP16/BF16 and INT4 make different promises

Representation

Floating point

Sign, exponent and fraction encode a wide dynamic range with non-uniform spacing. BF16 and FP16 both use 16 bits but distribute them differently.

Integer quantization

A limited codebook uses an explicit scale (and sometimes zero-point) to map real values into discrete codes. Spacing and clipping are chosen by calibration.

Do not conflate FP8 with INT8, or NF4 with uniform signed INT4. The later method section distinguishes these.

Integer codes need a reconstruction rule

Worked arithmetic · units and limits
$$q=\mathrm{clip}(\mathrm{roundEven}(w/s)+z,-8,7)$$
w, sweight; weight/codeOriginal scalar and positive scale
q, zinteger codesStored code and zero point
s = 0.25, z = 0, w = 1.83: q = 7; reconstruct ŵ = s(q − z) = 1.75.
Signed INT4 teaching map. NF4 uses a nonlinear lookup table instead.
Explain scale units and the order: divide, nearest-even round, add zero point, saturate, reconstruct. A zero point of zero simplifies the map but is not required by affine quantization.

Each scalar crosses four explicit operations

Complete CPU teaching example · invented weights
For scale 0.25 and signed codes −8 through 7, 1.83 divides to 7.32, rounds to 7 and reconstructs 1.75. Input 2.25 divides to 9, rounds to 9, clips to 7 and reconstructs 1.75. Errors reconstructed minus original are −0.08 and −0.50.

Rounding changes a value inside the code range

Worked arithmetic · units and limits
$$\hat w = 0.25\times7=1.75$$
wweight unitsOriginal scalar: 1.83
sweight units/codeChosen step: 0.25
qinteger coderoundEven(7.32) = 7
Signed error: ŵ − w = 1.75 − 1.83 = −0.08; absolute error = 0.08.
The rounded code fits. This small scalar error is not a whole-model quality score.
With chosen range [-8,7], 1.83 exceeds the largest reconstruction but rounds to a valid code; the clip operation itself does not alter the rounded integer. Distinguish rounded code clipping from the interval endpoint.

Clipping loses magnitude beyond the code range

Worked arithmetic · units and limits
$$q=\mathrm{clip}(9,-8,7)=7$$
w / sdimensionless2.25 / 0.25 = 9
qinteger codeRounded 9 saturates at 7
ŵweight units0.25 × 7 = 1.75
Error: 1.75 − 2.25 = −0.50. This exceeds the half-step rounding bound 0.125.
The half-step bound needs no saturation. A larger scale expands range but coarsens resolution.
Compare the same reconstructed endpoint with the previous scalar. The quantizer maps many out-of-range values onto the same endpoint, permanently losing their separation.

Ties are part of the reproducibility contract

Complete CPU teaching example · invented weights
Round-to-nearest ties-to-even maps −2.5 to −2, −1.5 to −2, 1.5 to 2 and 2.5 to 2. With scale 0.25, input 0.625 maps to 2.5 then 2 and reconstructs 0.5. A different tie rule can give code 3 and reconstruction 0.75.

Two signed four-bit codes occupy one byte

Complete CPU teaching example · invented weights
First row codes are −7, −2, 1, 7. Two’s-complement nibbles are 1001, 1110, 0001, 0111. Packing the earlier value into the low nibble gives byte 11101001, hexadecimal E9, then 01110001, hexadecimal 71. A four-value row uses two code bytes.

The byte is unreadable without a reconstruction rule

Complete CPU teaching example · invented weights
Unpack hexadecimal E9 into low nibble 9 and high nibble 14. Sign extension maps 9 to −7 and 14 to −2. Multiply by scale 0.25 to recover −1.75 and −0.50. Reading nibbles as unsigned or reversing their order reconstructs different weights.

The entire tiny projection fits on the page

Complete CPU teaching example · invented weights
Weight matrix has two outputs and four input features. Row 0 is [−1.83, −0.52, 0.24, 2.25]. Row 1 is [0.13, −0.88, 1.12, −2.40]. Input is [1, −2, 0.5, 1.5]. Scale 0.25 yields codes [−7, −2, 1, 7] and [1, −4, 4, −8].

A weight error becomes an activation-weighted error

Complete CPU teaching example · invented weights
Original row 0 dot input equals −1.83 + 1.04 + 0.12 + 3.375 = 2.705. Reconstructed row 0 gives −1.75 + 1 + 0.125 + 2.625 = 2.0. Full original output is [2.705, −1.15], reconstructed output [2, −0.25], so error is [−0.705, 0.9].

The same weights can create different output error

Complete CPU teaching example · invented weights
First-row weight error is [0.08, 0.02, 0.01, −0.50]. For input [1, 0, 0, 0], output error is 0.08. For [0, 0, 0, 10], error is −5. The activation distribution determines which errors matter.

One scale is cheap; one scale can be crude

Granularity

Per tensor

One mapping spans many values. Small metadata, but one outlier can expand the range for all channels.

Per channel / group

Different mappings protect local ranges. More scale metadata and layout constraints; the runtime must apply those scales in its kernels.

Use one high-magnitude channel as a thought experiment. The best granularity is a hardware-and-quality choice.

A distant outlier can erase a small group

Complete CPU teaching example · invented weights
Values are [−0.1, 0.2, −0.3, 0.4, 8, 9, 10, 11]. With one absmax/7 scale of 11/7, the first four round to zero. With groups of four, their scale is 0.4/7 and they retain codes [−2, 4, −5, 7]. The second group uses 11/7. Metadata doubles from one to two FP16 scales.

An affine zero point moves the zero code

Worked arithmetic · units and limits
$$\hat w=s(q-z)$$
sweight/codeHere 0.2
zinteger codeHere −2 represents real zero
qinteger codeHere roundEven(0.6/0.2)−2 = 1
w = 0.6 gives q = 1, then 0.2 × (1 − (−2)) = 0.6. Real zero maps to q = −2.
Scale and zero point must both survive serialization. Floating-point arithmetic can leave tiny residuals.
Do not subtract the zero point twice. The symmetric main toy uses zero point zero, whereas this affine extension deliberately uses minus two. Neither is the NF4 lookup.

Calibration chooses which error to reduce

Concrete choice before a GPU run

Weight-only error

Minimize average (ŵ − w)² over stored weights. A rare large value can dominate the scale.

Output error

Minimize ‖(Ŵ − W)X‖² over representative activations X. Important input channels can change the preferred scale.

X contains input feature vectors, not class labels. Held-out output behavior still decides whether a candidate is useful.

“Four bits” does not mean “four times smaller”

Common shortcut
Missing terms

Payload is only one part of a live GPU process.

Scales, zero-points, unquantized layers, padding, KV cache, activations, allocator reserves, workspaces and kernel code all consume memory.
The relative payload from 16 to 4 bits is 4×. The full process often is not. Quantify the difference later.

Choose what changes

Weights, activations and KV state live on different paths.

Ask students to point to the bottleneck from Topic 02 before choosing a quantization target.

The quantization target follows the tensor lifetime

Constructed decoder map · no performance claim
Projection weights persist across requests. Input activations change each token or batch. KV history persists for the lifetime of one sequence. W4A16 changes weights but leaves activation and KV precision separate.

W4A16 separates storage from arithmetic

Illustrative execution path · actual kernel must be observed
Packed four-bit weights and scales enter unpacking and dequantization. Reconstructed weights multiply sixteen-bit activations and accumulate in the kernel’s declared type. Dequantization may fuse inside a kernel or write a temporary buffer.

Quantizing both operands changes the scale product

Constructed W8A8 dot product · zero points are zero
Weight codes [2, −3] at scale 0.1 reconstruct [0.2, −0.3]. Activation codes [4, 5] at scale 0.2 reconstruct [0.8, 1]. Integer dot is 2 × 4 − 3 × 5 = −7. Multiplying by 0.1 × 0.2 gives −0.14, matching the reconstructed float dot. Actual accumulation depends on the kernel.

Failure: “loads” does not mean “accelerates”

Production scenario A

Detection

Cold load takes longer; prefill and decode timing regress. Logs show conversion; profiler shows dequantize or generic kernels instead of the expected path.

Calibrate and deploy

Same bit width, different optimization and kernel contracts.

PTQ and QAT are different workflows; the lab performs a bounded post-training load-time quantization.

When is the quantizer chosen?

Workflow

Post-training quantization

Start with a trained checkpoint, choose scales/codes on calibration data, then validate held-out tasks. Usually cheaper than retraining.

Quantization-aware training

Expose the model to quantization effects during training/fine-tuning. Can recover quality but adds data, compute and training risk.

Neither route removes the need to test the exact runtime artifact on the target device.

Calibration data is a design choice

Representativeness
PTQ INPUT
Match the deployment distribution

Code, math, structured outputs, long context and languages may activate different channels. A tiny generic sample can choose scales that look good on average but fail a critical bucket.

Keep calibration and evaluation separate. No private hidden judge prompts enter calibration.

Equivalent scaling changes the quantizer’s error

Constructed local mechanism · AWQ motivation
For W [0.13, 2] and x [10, 1], the dot product is 3.3. Scale channel 0 by four: W prime [0.52, 2], x prime [2.5, 1], same float dot 3.3. Fixed-step 0.25 quantization gives unscaled output 4.5 versus scaled output 3.25. Error changes from 1.2 to −0.05.

Correlated input features permit error compensation

Constructed two-weight reconstruction problem · GPTQ motivation
One calibration input [1, 1], weights [0.6, 0.6], reference output 1.2. Quantizing the first weight to 1 leaves remaining weight 0.2 to preserve output before its own quantization. Rounding it to 0 gives output 1, error −0.2. Independent rounding gives [1, 1], output 2, error 0.8.

Saved traffic must exceed added work

Illustrative serial transfer-plus-overhead model
At 300 GB/second effective bandwidth, 6 GB weights need 20 ms and 1.55 GB need 5.167 ms. Adding 2 ms work gives 7.167 ms. If baseline effective traffic falls to 0.6 GB through reuse, its model time is 2 ms. A 2 ms added overhead can then erase a gain.
