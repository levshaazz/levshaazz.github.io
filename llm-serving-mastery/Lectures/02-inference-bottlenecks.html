Separate the phases

Prefill and decode run the same weights through different shapes.

The phase distinction explains why one average “model latency” cannot predict a serving workload.

Prefill consumes the known prompt

Illustrative token sequence
Four known prompt token IDs enter one prompt-processing phase. That phase produces KV state for the prompt and the distribution from which the first output token is selected. Positions can be processed in parallel subject to causal attention. Four boxes represent token IDs, not four words. Ask for one falsifying observation before proposing an optimization.

One output chain advances sequentially

Illustrative token sequence
Output y1 is fed back to compute y2; y2 is fed back to compute y3. The retained KV state grows at each step. Different requests may advance in the same iteration. For n output tokens there are n−1 gaps after the first output. The first output comes from prompt processing. Ask for one falsifying observation before proposing an optimization.

Follow the bytes

Capacity tells whether data fits. Bandwidth and reuse tell how fast it feeds compute.

The word “memory” hides multiple levels and three separate questions: fit, movement rate, and access delay.

Bytes cross different physical boundaries

Logical memory path
CPU DRAM crosses a host link to GPU device memory. On the GPU, L2 caching and per-SM on-chip storage help feed arithmetic. Registers are thread-local and shared memory is programmer-managed; this is not a list of interchangeable capacities. HBM versus GDDR depends on the GPU. Shared memory/L1 organization is architecture-dependent; this map is not a strict mandatory serial route. Ask for one falsifying observation before proposing an optimization.

Three memory failures need three tests

Diagnostic map
Capacity asks whether live tensors fit and is tested with an allocation ledger. Bandwidth asks bytes per second and needs traffic/time evidence. Latency asks whether dependent fetches can be hidden and needs a timeline or stall evidence. An OOM does not prove bandwidth saturation; high free memory does not prove fast access. Choose evidence for the mechanism. Ask for one falsifying observation before proposing an optimization.

Tensor role predicts desired placement

But software does not control every hit

Long-lived

  • weights: device memory, reused by kernels
  • KV cache: device memory, grows per request
  • allocator pools: reserved for reuse

Short-lived / tiled

  • activations and workspace
  • L2-resident reused lines when lucky
  • shared-memory tiles and registers
“Stored in HBM” does not mean every access necessarily reaches HBM; caches mediate actual traffic.

Reuse is the bridge from bytes to operations

The performance lever
DATA REUSE
Perform more useful operations before the same data must be fetched again from a slower memory level.

Batching reuses weights across token rows; tiling reuses blocks on chip; fusion keeps intermediate values closer to compute.

Reuse does not reduce model semantics. It reorganizes execution and data movement.

Useful bytes and transferred bytes can differ

Illustrative access pattern
Four neighboring threads access four adjacent useful elements in one conceptual memory segment. Four scattered accesses span four segments instead. The useful payload is the same but the fetched footprint can differ. Segments are schematic, not a claim of a universal CUDA transaction size. Alignment, element width and cache state matter. Ask for one falsifying observation before proposing an optimization.

Fusion removes intermediate memory trips

Worked traffic accounting
Three elementwise stages over N elements materialize two intermediates: read X, write A, read A, write B, read B, write Y gives six N element transfers. Fusing stages can reduce this to read X and write Y, two N transfers. For 1 Mi elements at 2 bytes each: 12 MiB versus 4 MiB idealized payload. This is not a guaranteed threefold wall-time speedup. Ask for one falsifying observation before proposing an optimization.

Keep attention intermediates close to compute

Algorithmic IO sketch
A naive implementation writes an S-by-S score matrix to device memory and reads it back. An IO-aware tiled attention method loads blocks of Q/K/V and updates online softmax/output state on chip, avoiding that full materialization. Exact attention with floating-point rounding differences; logical persistent KV and the output-token dependency still remain. Ask for one falsifying observation before proposing an optimization.

What stays resident is not what is read per second

Illustrative KV lifecycle
At each decode step one new key/value position is appended. The query attends a growing retained history. Resident capacity grows by one position per sequence, while read demand depends on history, reuse and kernel implementation. A logical history-access count is not measured HBM traffic. The selected token has no cache entry until the next forward pass. Ask for one falsifying observation before proposing an optimization.

Do not add allocated bytes to reserved bytes

Illustrative allocator nesting
Device process memory includes a caching allocator pool and allocations outside it. Within the pool, live allocated tensors occupy part of the reserved space; the rest can be reusable. Reserved and allocated are not disjoint terms. Peak allocated/reserved are in-process counters. A between-cell nvidia-smi sample can miss the peak and includes a different boundary. Ask for one falsifying observation before proposing an optimization.

Identical prefixes can share work—not all state

Illustrative prefix ownership
Two requests share an identical reusable prefix but have separate continuation tokens and KV. Reuse requires matching model/tokenization/position and safe isolation. The prefix cannot be evicted while still referenced. This is the ownership question; cache-key design and block implementation belong to later engine topics. Similar text is not necessarily identical token state. Ask for one falsifying observation before proposing an optimization.

A CPU launch can finish before device work does

Constructed asynchronous timeline
CPU enqueue takes 1 ms while device work completes at 11 ms. A host timer without a completion barrier can report only the enqueue interval. A synchronized wall interval waits for the device; events bracket a device-stream interval. Event intervals can include idle time while Python launches later kernels. Do not label them summed CUDA kernel time. Ask for one falsifying observation before proposing an optimization.

Optimize the share of wall time, not a table rank

Worked Amdahl example
In 100 ms wall time, kernels occupy 60 ms; a GEMM is 55 percent of kernel time, so only 33 ms of wall time. Speeding that GEMM by 10 percent saves 3 ms, reducing total time to 97 ms: a 3.09 percent speedup. Assumes unchanged other work and no overlap. A 3% time reduction is a 100/97−1 = 3.09% throughput speedup for serial repetitions. Ask for one falsifying observation before proposing an optimization.

A bounded experiment has a stopping rule

Illustrative measurement workflow
Freeze the manifest, warm the service, measure one bounded load point, check guardrails, and either stop or increase load. Always retain raw records and verify resources return to baseline. Stop on resource growth, errors or missed safety limits. A successful one-request lab does not authorize a broad unattended load sweep. Ask for one falsifying observation before proposing an optimization.
