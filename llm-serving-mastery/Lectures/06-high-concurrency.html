Two finite resources, two different failures

Два конечных ресурса, два разных отказа

Topic 06 · draft · bounded examples

Compute

SM occupancy and batch compute: prefill of a new request is a full extra pass — it competes with every resident decode.

Вычисления

Занятость SM и батчевые вычисления: prefill нового запроса — целый лишний проход, он конкурирует с каждым резидентным decode.

KV memory

36 KiB per retained position per request: grows with context and clients until admission or preemption stops it.

Память KV

36 КиБ на удерживаемую позицию на запрос: растёт с контекстом и клиентами, пока допуск или вытеснение не остановят рост.

Throughput curves die from one of these two ceilings. The experiment exists to tell them apart: a compute knee shows TPOT growth; a memory knee shows admissions blocked and preemption recompute. Same graph, different mechanism, different fix.

KV compression: a different answer to the same problem

Сжатие KV: другой ответ на ту же проблему

Topic 06 · draft · bounded examples

What we computed

Standard multi-head attention: 36 KiB per position, 72 MiB per full-context request. The budget is arithmetic — a ceiling you can compute before measuring.

Что мы посчитали

Стандартное multi-head attention: 36 КиБ на позицию, 72 МиБ на запрос с полным контекстом. Бюджет — арифметика: потолок, который можно посчитать до измерений.

What MLA does

Multi-head Latent Attention (DeepSeek, FlashMLA): compresses K and V into a shared latent representation. The KV bill per position drops by an order of magnitude — the same GPU holds far more resident contexts.

Что делает MLA

Multi-head Latent Attention (DeepSeek, FlashMLA): сжимает K и V в общее латентное представление. KV-счёт на позицию падает на порядок — тот же GPU держит куда больше резидентных контекстов.

Both approaches answer the same question: KV memory is the bottleneck. We teach the arithmetic ceiling because it is transparent and falsifiable. MLA is the production answer when the ceiling is too low. Connect: the knobs of Topic 07 move the ceiling; MLA removes it entirely by changing the representation.

Beyond continuous batching: the async scheduler

Дальше непрерывного батчинга: async-шедулер

Topic 06 · draft · bounded examples

What you just walked

One step at a time: prefill takes a step, everyone waits. The Topic 06 waterfall shows this as grey bands widening when a new request arrives.

Что вы только что прошли

По одному шагу: prefill занимает шаг, ждут все. Водопад темы 06 показывает это серыми полосами, расширяющимися с приходом нового запроса.

What production engines do

The CPU prepares the next batch while the GPU computes the current one — zero dead time between steps. DeepInfer (DeepSeek, Apache-2.0) made this their default; vLLM is moving the same direction.

Что делают продакшен-движки

CPU готовит следующий батч, пока GPU считает текущий, — нулевое мёртвое время между шагами. DeepInfer (DeepSeek, Apache-2.0) сделал это своим дефолтом; vLLM движется туда же.

This is the next level of the same mechanism. The waterfall grey bands shrink because the scheduler is never idle. Students should connect: async scheduling = the batching economy applied to the scheduler itself, not just to the batch composition.
