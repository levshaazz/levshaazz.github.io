Works on my machine is a contract breach

Topic 09 · draft

What you own now

The Topic 08 gateway validates, queues with honest 429s, maps errors, cancels. But it lived on whatever Python and pip state the host had.

What changes

The app becomes an immutable image with pinned dependencies. An image is a layered blueprint; a container is an ordinary process on your machine running that blueprint in isolation — same kernel, no virtual machine.

Frame the transition: Topic 08 built the API contract; Topic 09 makes it survive transport. Zero-Docker students: the official <a href="https://www.docker.com/resources/what-container">what-is-a-container</a> explainer and the <a href="https://www.docker.com/101-tutorial">Docker 101</a> hands-on cover this ground with pictures before the lab applies it.

Same app, three hosts, three behaviors

Topic 09 · draft

The drift

Host A: Python 3.10, old fastapi. Host B: 3.12, fresh install. Host C: a stale venv. Same code, three different services — maybe three different bugs.

The admission

"It worked yesterday" is not reproducibility. A floating latest tag is a deferred dependency break. A base image tag is not a version.

The env-drift story: ask which of the three hosts is the real one. Answer: none — the image is. Set up the motif: the image is the blueprint of a mobile kitchen; the container is the working kitchen; layers are its modules.

The build cache is a chain of layers

Topic 09 · draft

What a cache hit means

Layer k is reused only if layers 1..k are all unchanged. A stack is only as cacheable as its most frequently edited layer.

The rule that falls out

Order instructions from least to most frequently changing: system packages, then dependency files, then code. The order IS the cache policy.

Intuition before the formula: students pick the layer order from three options and freeze the prediction before building. The cache-hit condition gets its formal shape only in the book chapter, after docker history.

Lean is a contract with the network

Topic 09 · draft

Multi-stage builds

Compilers and pip cache stay in the builder stage; the runtime stage copies only the installed artifacts and code. The image ships none of the build machinery.

The context is part of the image

A .dockerignore keeps journals, virtualenvs and VCS state out of the build context. What the context never sees, no layer ever remembers.

Episode 3. Every megabyte is paid on every pull. The lab builds a deliberately naive v0 (full base, code copied before pip, root, no healthcheck) and then a lean v1 — the size delta becomes the student own data.

Probe across the boundary

Topic 09 · draft

Mapping the worlds

Ports are mapped (-p host:container), configuration travels in env (-e), memory arrives as a wall (--memory).

The probe suite

Health, one completion, then an overload burst. The Topic 08 suite must pass UNCHANGED against localhost:mapped-port — that is the point of the contract.

Episode 4: the T08 probe suite is reused verbatim. If a probe fails only inside the container, the image — not the contract — is the suspect. Limits are admission control for containers: exceed the wall and the kernel decides.

The size of an image is the sum of its layers

Topic 09 · draft
$$|\mathrm{image}| \;=\; \sum_{i=1}^{n} |\mathrm{layer}_i|$$
\(|\mathrm{image}|\)bytesWhat every pull and every extract pays
\(n\)layersOne per Dockerfile instruction
\(|\mathrm{layer}_i|\)bytesThe diff a single instruction adds
One code-file edit rebuilds one small layer — only while the dependency layer sits below the code layer.
Shared base layers deduplicate on one host; the sum is the pull envelope, not disk footprint. Bytes are the student own build.
The lab itemizes every layer with docker history against the frozen plan; a layer that cannot be justified is removed.

Cold start is a sum of named terms

Topic 09 · draft
$$t_{\mathrm{cold}} \;=\; t_{\mathrm{pull}} + t_{\mathrm{extract}} + t_{\mathrm{python}} + t_{\mathrm{init}}$$
\(t_{\mathrm{pull}}\)secondsNetwork-bound: fetching layers not present locally
\(t_{\mathrm{extract}}\)secondsScales with the sum of layer sizes
\(t_{\mathrm{python}} + t_{\mathrm{init}}\)secondsInterpreter start plus imports and the first health answer
A warm restart keeps the local layers, so it pays only the last two terms. Cut the DOMINANT term, not a random one: a smaller base shrinks extract, a prebaked artifact removes a download.
Term sizes are machine- and network-dependent. The lab measures cold and warm on the student machine, before and after one justified change — improvement without a named mechanism is superstition.
This is the startup-economics equation. The lab journals both paths with progress bars, then applies one change (v0 to v1: slim base, fewer layers, fewer packages) and re-measures, attributing the delta to the named mechanism.

Cold versus warm: measured, not hoped

Topic 09 · draft

The measurement

Cold: remove, create and start the container, watch /health. Warm: stop and start the same container. Both journaled with progress bars on YOUR machine.

The attribution

The v0-to-v1 delta is claimed only with a named mechanism: smaller base means shorter extract; fewer packages mean faster interpreter and init.

Honest startup economics: the pull term is declared, never measured in the lab (it belongs to the network, not to the image). Second-scale effects on local disk; not comparable across machines.

Security defaults, not security options

Topic 09 · draft

Non-root and pinned

A dedicated user inside the container; base and dependencies pinned by tag, ideally by digest. A tag is not a version; a digest is.

Layers remember everything

A secret added in one instruction and deleted in the next still lives in the earlier layer. History reads what you erased.

Episode 8: minimal surface, no secrets in layers, pinned inputs. The SBOM stretch turns these into an inventory: one tool, one image — an inventory, not a security certification.

Reading exit codes and logs as data

Topic 09 · draft

The vocabulary

137 = 128 + 9 (SIGKILL), the classic cgroup OOM. 1 = the command failed, read the tail. 125 = the daemon itself refused. 127 = command not found.

The discipline

Cause, evidence, fix — three fields per drill, journaled. "It crashed" is not a diagnosis; "exit 137 under a 64 MB wall" is.

Principle: debugging is part of the plot. The diagnosis function maps exit code plus log tail to the three fields; the lab freezes both drills into the journal with their evidence tails.

Resource limits are admission control

Topic 09 · draft

The wall

CPU and memory limits turn best-effort sharing into a contract: exceed the wall and the kernel kills — no Python exception, no traceback, just the exit code.

The kinship

The bounded queue answered 429 in user space; the cgroup wall answers SIGKILL in kernel space. Honest refusal beats silent degradation at both layers.

Connect back to Topic 08 admission: same value, different enforcement point. Students feel the difference between a graceful rejection they designed and a kill they provoked by exceeding a declared limit.

SBOM and the supply chain (stretch)

Topic 09 · draft

What an SBOM is

A software bill of materials: every OS and Python package in the image, with versions. One image, one inventory, generated by a plugin or scout command.

What it makes obvious

Floating base tags; dependencies without exact versions; files that were "deleted" but still live in layer history. Three risks, three sentences.

The stretch keeps its own limit: one tool, one image — an inventory, not a certification. The lab saves the inventory when the tool exists and prints an honest instruction when it does not.

The fleet story

One image, many machines

Identical behavior everywhere is the precondition for everything that follows: scaling, orchestration, rollback. The unit of deployment is immutable.
