One pass: order, receipt, serving window

Topic 08 · draft
Five stages, each owning one decision: the client issues a request; validation enforces public caps at the door; admission takes a service slot, a bounded waiting slot, or refuses with 429; the engine generates; the error map turns every terminal outcome into one honest status code. Identity: the id travels the whole pass

Topic 08 · draft

Assigned at the door

The gateway mints the id before validation, admission or generation. From that moment the request has a name in every log line.

Read in four places

Reply header, engine journal, error body, metrics snapshot. The error body carries it verbatim: the retrying client correlates its own attempts.

The bounded queue: latency you promised to nobody

Topic 08 · draft

Unbounded queue

Every arrival is accepted, depth grows, and the delay is paid by clients who were never asked. The pager sees nothing until the timeouts arrive.

Bounded queue

Capacity in service, a finite waiting line, and an honest refusal beyond. Depth becomes a declared number; refusal becomes a designed answer.

Episode 4 intro. The queue is the Topic 06 saturation lab wearing an API: same mechanism, now visible as slots. Ask: who consents to wait in an unbounded queue? Nobody — that is the point.

Queue depth obeys Little’s law

Topic 08 · draft
$$L = \lambda W$$
\(L\)requestsMean in-flight: queue plus service
\(\lambda\)req/sArrival rate
\(W\)secondsMean residence per request
Declared mock knobs: W = 0.15 + 0.02 × 16 = 0.47 s, so λ = 10 req/s buys L ≈ 4.7 — already past the admit ceiling of 4.
Little’s law locates the knee, not the tail: percentiles come from the journal. Every knob here is mock-declared, never a vLLM measurement.
The one formula of the block, and it appears only after the economy is visible. The knee lambda = (c + q) / W is the same law rearranged: with c = 4 slots and q = 4 waiting seats, refusals start at 17 requests per second.

429 with Retry-After is an honest answer

Topic 08 · draft

What the client learns

Now: refused, with a declared pause and the request id. The retry is a decision, not a gamble — backoff is computable.

What the pager learns

A rising rejected counter is a designed signal, not silent rot. Refusal is capacity speaking; an endless queue is capacity lying.

Episode 4 close. The lab overload drill fires 24 clients at a 4+4 pool and checks the observed share against the frozen envelope: 8 served, 16 refused. A mismatch is interesting data — name the mechanism, do not twist the mock.

Timeouts and cancellation: a leaving client stops paying

Topic 08 · draft

The deadline

Every admitted request carries a budget. A queue wait beyond it becomes 504 with the id — the slot returns to service, the client learns why.

The disconnect

A closed socket is a decision by the client. The gateway must stop the generation, journal outcome cancelled, and count the tokens burned for nobody.

Episode 5. The lab shows the bug FIRST: without the watcher, an abandoned generation runs to completion and the journal happily says completed. Fixing it is the last and freest student function — level C, contract only.

Honest errors: every outcome maps to a code with a next action

Never 200-with-error-body

Topic 08 · draft

The silent break

A 200 envelope with an error inside passes every shallow health check, poisons the client’s success path, and corrupts its retry logic without a trace.

The honest split

The status code is the first truth a client reads. Success and failure never share an envelope; the body explains, the code decides.

Episode 6 close. This is not aesthetics: clients build automation on the code. Ask the room where THEY have seen a 200 hiding a failure — payments and proxies are the usual confessions.

Streaming: the same mechanism, one frame later

Topic 08 · draft

Frames as they generate

Server-sent events deliver text while the engine decodes. The client sees progress; the gateway still owns admission, deadline and the error map.

Mid-stream cancellation

A client gone at frame k is the Episode 5 mechanism one frame later: stop the task, journal the waste. No new machinery — the same watcher.

Episode 7. Streaming tempts teams to bypass the pass: frames feel free, so admission feels optional. The rule holds frame by frame: the ticket is being cooked or honestly refused, and a half-cooked ticket is still waste on the books.

Structured outputs: schema in, validated JSON out

Topic 08 · draft

The request

An optional response schema rides with the prompt. The engine constrains decoding; the gateway validates the reply against the SAME schema before answering.

The violation path

A reply that breaks the schema is a visible 422 with the exact path — not a silent cast, not a 200 with apologies. The client sees which field lied.

Episode 8. The mock returns declared synthetic JSON; the validator is the student’s function. The fixture deliberately breaks the schema (wrong enum, string where a number belongs) so the violation path is read, not imagined.

Observability: counters you planned

Topic 08 · draft

The five numbers

Accepted, rejected-429, cancelled, in-flight, waste. Each exists because a named decision needs it — a metric you did not plan is a metric you will fake.

The honest zero

At snapshot time cancelled reads zero: cancellations arrive only after the watcher block. A zero that is explained beats a number that is decorated.

The bridge to Topic 09: the contract travels

What T09 changes

Nothing about the pass. The same gateway, the same probes, the same 429s — packaged as an immutable image so behavior stops depending on the host.

Why it must wait

A contract that is not yet honest cannot be frozen into an image. First the pass refuses correctly; then the image preserves the refusal everywhere.
