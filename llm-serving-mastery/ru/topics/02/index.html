Результаты обучения

  1. Проследить RMSNorm, Q/K/V, RoPE, attention, остаточные сложения и gated MLP от буквального входа до выбранного токена.
  2. Предсказать, как prefill и декодирование по-разному нагружают GPU.
  3. Вывести байты на токен KV-кэша из зафиксированной конфигурации модели.
  4. Использовать синхронизированные тайминги и выбирать правильный уровень профилировщика.
  5. Свести ручной расчёт с измеренными данными.

Чек-лист приёмки

  • Протокол v2: две зафиксированные модели; B1 — вход 128/4096 × выход 32/128, плюс B4/128/32; пять прогонов на случай.
  • Smoke-проверка при старте проходит до матрицы; каждый прогон сохраняется контрольной точкой; частичное — не полное.
  • Синхронизированные интервалы по wall-времени и CUDA-событиям — это не суммы kernel и не HTTP-задержка.
  • Сообщать сырой разброс, согласованные скорости/ритм batch, учёт KV и фальсифицируемую roofline-гипотезу.
  • Оба фокусных трейса для 0.5B — P128/P4096, O8; накладные расходы профилировщика и пересечения атрибуции показаны явно.
  • Валидатор CPU-артефактов проходит; он проверяет согласованность, а не подлинность.

Открыть первоисточники

  • Qwen2 decoder implementation · Transformers 4.51.3 — Exact pre-norm residual order, Q/K/V biases, rotary coordinates, gated MLP and backend dispatch in the captured runtime. Conceptual attention matrices need not be materialized by SDPA.
  • vLLM / PagedAttention — Paged KV state and the serving-system design trade-off.
  • Roofline model · Berkeley technical report (2008) — Compute and bandwidth upper bounds; does not predict queue or launch time.
  • FlashAttention — IO-aware attention tiling and memory traffic.
  • DistServe — Prefill/decode interference and the disaggregation trade-off; not evidence about this course's one-GPU run.
  • Pinned Qwen2.5-3B configuration — Layer, KV-head, and head-dimension inputs to the worked KV calculation.
  • Pinned Qwen2.5-0.5B-Instruct configuration — Pinned model dimensions for the teaching notebooks; use the recorded runtime and actual selected attention path.
  • PyTorch 2.14 · CUDA execution and memory — Asynchronous execution, synchronization and the caching allocator. Allocated, reserved and whole-device memory are different quantities.
  • PyTorch 2.14 · profiler — Record operator and device activity. Operator attribution and physical kernel events can overlap; do not sum them as disjoint time.
  • CUDA C++ Best Practices Guide — Memory access, bandwidth, launch and measurement guidance. Living documentation; match the installed CUDA/runtime and hardware.
  • Pinned Qwen2.5-1.5B-Instruct configuration — Immutable dimensions for the Topic 02 larger model. A model configuration does not establish measured speed.
  • GQA: grouped-query attention — Why multiple query heads can share fewer KV heads and how that changes logical KV payload.
  • Sarathi-Serve — Throughput/latency trade-offs and chunked prefill. Paper measurements are not a performance prediction for the course host.

Эксперименты и записанные доказательства

  • Move across the roofline — Does doubling arithmetic intensity still increase the ceiling after the ridge?
  • Budget live KV tokens — Why can logical KV payload fit while a real service still runs out of memory?

Topic 02 · protocol v2 — 50 raw trials and two focused profiles on RTX 5070 Ti. Five repeats per case; unresolved timing variance. Not a stable performance bar.

Topic 02 · one exact prompt, token by token — A literal prompt, actual tokenizer IDs and output, per-call clocks and memory. One instrumented natural-EOS replay on RTX 5070 Ti; CPU playback needs no download. Separate from the required synthetic v2 matrix and never a performance baseline.

Topic 02 · inside one decoder block — One offline prefill and one decode with small layer-0 tensor slices and final logits. CPU attention reconstruction and a separate tiny arithmetic fixture explain the operations; neither supplies benchmark timings or observed CUDA attention weights.

Topics 01–04 · historical instructor rehearsal — Pinned offline single-host teaching runs. Topic 02 here is historical v1 (current v2); Topics 03 and 04 are historical v2 (current instrumented v3). These are teaching smokes, not full benchmarks or controlled cross-version speedups.
