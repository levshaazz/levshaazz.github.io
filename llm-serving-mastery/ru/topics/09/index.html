Docker для инференса LLM

Шлюз из Темы 08 становится неизменяемым образом: упорядоченные слои как политика кэша, компактный зафиксированный multi-stage build, тот же API-контракт, проверенный через границу контейнера, экономика холодного/тёплого старта, измеренная на собственной машине студента, намеренные дриллы отказов (дрейф тега, OOM по лимиту памяти) и взгляд на цепочку поставок через SBOM. CPU-образы — для всех; CUDA/vLLM-вариант — демонстрация владельца.

Результаты обучения

  1. Объяснить, что образ — это упорядоченные слои, и предсказать, какие правки инвалидируют кэш сборки.
  2. Написать компактный, зафиксированный non-root образ и разложить его размеры по слоям.
  3. Проверить полный API-контракт через границу хост–контейнер.
  4. Измерить холодный и тёплый старт и сократить доминирующее слагаемое одним обоснованным изменением.
  5. Диагностировать дрейф тега и OOM по лимиту памяти по логам и кодам выхода.
  6. Собрать SBOM и назвать риски цепочки поставок, которые он вскрывает.

Требуемые артефакты

  • Dockerfile + .dockerignore + lockfile
  • build-plan.json (замороженные прогнозы)
  • учёт размеров слоёв
  • измерения старта + журнал дриллов

Чек-лист приёмки

  • дизайн-аудит чист
  • преподавательский эталон: 0 ошибок без Docker daemon (охраняемые ячейки честно пропускаются)
  • набор проб проходит через границу
  • измерения помечены как выполненные на собственной машине студента

Обязательное чтение
