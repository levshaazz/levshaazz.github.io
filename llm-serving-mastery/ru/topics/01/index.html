Результаты обучения

  1. Проследить потоковый запрос через производственные границы.
  2. Разделить спрос сервиса, ожидание в очереди, TTFT, ритм декодирования и задержку завершения.
  3. Перевести SLO и рабочую нагрузку в гипотезу о ёмкости.
  4. Объяснить поведение при перегрузке и обязательства по отмене запросов.

Чек-лист приёмки

  • Зафиксированы ревизия модели и токенизатора, runtime, GPU, dtype и счётчики токенов.
  • Холодная загрузка и прогрев отделены от таймингов запросов.
  • Текстовые фрагменты стрима не называются отдельными токенами.
  • Данные одиночного запроса не подаются как заявление о конверте конкурентности или ёмкости.

Обязательное чтение

  • Orca: планирование на уровне итераций
  • vLLM / PagedAttention
  • DistServe: интерференция prefill и декодирования

Открыть первоисточники

  • Orca: iteration-level scheduling — Why scheduling can change the active batch between iterations; not a benchmark for this host.
  • vLLM / PagedAttention — Paged KV state and the serving-system design trade-off.
  • DistServe — Prefill/decode interference and the disaggregation trade-off; not evidence about this course's one-GPU run.
  • Pinned Qwen2.5-0.5B-Instruct configuration — Pinned model dimensions for the teaching notebooks; use the recorded runtime and actual selected attention path.
  • PyTorch 2.14 · CUDA execution and memory — Asynchronous execution, synchronization and the caching allocator. Allocated, reserved and whole-device memory are different quantities.
  • The Tail at Scale — Tail latency in large services; interpret percentiles with a declared population and failure policy.
  • Sarathi-Serve — Throughput/latency trade-offs and chunked prefill. Paper measurements are not a performance prediction for the course host.

Эксперименты и записанные доказательства

  • Trace the request path — Where could impossible work be rejected before entering an unbounded queue?
  • Admission under a burst — Does accepting every request improve the number completed before a deadline?
