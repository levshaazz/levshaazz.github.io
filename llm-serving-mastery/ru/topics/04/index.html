Результаты обучения

  1. Проверить обслуживаемую идентичность и реализовать страж допуска на отрисованных токенах с лимитом вывода.
  2. Объяснить выбор токенов и оценить полные, валидные и корректные предсказания матрицей ошибок 3x4 по всем попыткам.
  3. Заморозить лимит вывода и политику формата, выполнить ограниченный vLLM smoke и пробы задач на калибровке/held-out, диагностировать фактические ошибки.

Student work sequence

  1. A: идентичность и ваш страж отрисованного контекста
  2. B: выбор токенов и ваша оценка по всем попыткам
  3. C: фактические ошибки Qwen, матрица ошибок и вмешательство в сэмплирование
  4. D: замороженные лимит/формат, свежая проба задачи и инженерная записка

  • Inspect actual Qwen FP16 errors and explain the measured confusion matrix.
  • Declare one-factor candidates, compare fresh calibration results, then freeze a chosen policy before loading held-out.
  • Save CPU work, fresh GPU evidence and a boundary-aware engineering memo separately.

Открыть первоисточники

  • WHATWG · parsing server-sent events — UTF-8, line endings, multiline data, comments and blank-line dispatch. The application-level finish/DONE contract is separate from SSE framing and browser EventSource reconnection.
  • vLLM / PagedAttention — Paged KV state and the serving-system design trade-off.
  • Pinned Qwen2.5-3B configuration — Layer, KV-head, and head-dimension inputs to the worked KV calculation.
  • Pinned Qwen2.5-0.5B-Instruct configuration — Pinned model dimensions for the teaching notebooks; use the recorded runtime and actual selected attention path.
  • vLLM OpenAI-compatible server — Routes, model identity, and chat-template behavior; check version-specific caveats.
  • vLLM serve CLI — Serve flags and bounded startup settings; recorded run values are in course evidence.
