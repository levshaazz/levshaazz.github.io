Kubernetes для LLM-сервинга: GPU Operator и Helm

Флот у вас уже есть — compose-движки с лимитами, журнал с хэш-цепочкой, shard-реплики. Kubernetes превращает ручной цикл в декларативное состояние: под наследует ведомость (16+4)/p + 1.5 ГиБ и холодный старт 165 с, бюджет startupProbe закрывает загрузку (5 × 40 = 200 с ≥ 165 с), rolling update с maxUnavailable 0 держит пол ёмкости, а Helm-релиз — это append-only история, где откат создаёт новую ревизию. GPU-словарь — Operator, time-slicing, MIG — остаётся честным словарём; лаба — это заявленная учебная модель кластера, не ваш кластер.

Результаты обучения

  1. Размерировать под LLM-движка из курсовой ведомости и объявить Guaranteed: requests == limits, nvidia.com/gpu: p.
  2. Выставить бюджет startupProbe с названным запасом над загрузкой; объяснить, почему liveness не должен убивать грузящийся под.
  3. Выбрать maxUnavailable/maxSurge так, чтобы rolling update не ронял ёмкость; читать пол как replicas − maxUnavailable.
  4. Вести helm-релизы: upgrade, history, rollback — и объяснить, почему откат создаёт ревизию 4, а не перематывает историю.
  5. Назвать слова шаринга GPU (time-slicing, MIG, MPS) и их компромиссы изоляции.
  6. Собрать runbook отката: числа манифеста, бюджет пробы, команда и ревизия, которая появится после отката.

Требуемые артефакты

  • pod-manifest.yaml (requests == limits из ведомости; nvidia.com/gpu: p)
  • probe-budget.md (period × threshold против 165 с холодного старта, запас назван)
  • rollout-plan.md (replicas, maxUnavailable/maxSurge, пол)
  • release-history.txt (ревизии 1→4 с записью отката)
  • rollback-runbook.md (числа, команда, ожидаемая ревизия)

Чек-лист приёмки

  • память пода равна (16+4)/p + 1.5 ГиБ при requests == limits
  • бюджет пробы ≥ 165 с с названным запасом над медианной загрузкой
  • пол роллаута удержан: ёмкость не ниже replicas − maxUnavailable
  • rollback из истории [1,2,3] даёт ревизию 4 с содержимым ревизии 1
  • в runbook названа точная ревизия, существующая после отката

Обязательное чтение

  • Kubernetes docs — классы QoS подов; Configure Liveness, Readiness and Startup Probes
  • Helm docs — helm history / helm rollback (откат создаёт новую ревизию)
  • NVIDIA GPU Operator docs — driver container, toolkit, device plugin; time-slicing vs MIG
  • llm-d — Model-Aware Readiness Probes (Ready только после загрузки весов)
  • KubeCon NA 2026, OpenAI — Rolling Out LLM Inference Engines on Kubernetes
